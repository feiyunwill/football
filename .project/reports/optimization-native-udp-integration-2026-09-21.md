## 实现与验证

实际原生客户端现在由同一个 BasicIntegratedFrameSyncClient 状态机实例化 TCP 与可靠 UDP。加载、输入发布、凭证换代、重连和回放逻辑共用；UDP 使用已验证的主动连接器，服务端实例化 BasicEngineSessionServer<NativeUDPTransport>。同步旧协议仅保留于 TCP，UDP 明确要求原生产品契约。

加载取消检查使用实际客户端和准备后的 GameEnv，覆盖有效回执、伪造密钥、伪造代际、静默及连接关闭。其计时是加载检查点至客户端 stop 完成，不能替代真实窗口 Q 键至整个进程退出的 250ms 验收。后者已有超时，仍需优化。

## 两项具体缺陷

1. **关闭前丢失末尾报文。** 旧公共服务端只看应用写入队列是否清空。可靠 UDP 的写入完成仅代表报文已入队，服务端约下一轮维护就关闭流，删除仍未确认的取消回执或拒绝报文。实际 UDP 中继丢弃首次末尾报文后，两种构建的旧实现均有两项失败。新传输策略检查可靠层的待确认报文，确认输出排空后再关闭；重试及既有截止时间仍有界。
2. **立即停止 IO 时保留接收回调。** 公共服务端的关闭原本只投递到 IO；若随后立即停止 IO，UDP accept 状态仍保存捕获服务端的回调，形成所有权环。新增的“未派发任何 IO 即停服”和“应用读取待完成时停服”覆盖实际停止顺序。旧六项 Debug 对照泄漏 273202 字节 / 84 次分配；新策略先同步解除逻辑接收回调和流回调，物理 socket 关闭仍由监听器执行器串行处理，六项 Debug 检查无泄漏。

这组使用真实公共服务端、UDP 连接器和实际 socket 中继，引擎为显式 oracle。它不是完整 GameEnv 对局证据。首次 A 的旧 ASan 泄漏与失败保留；B 增加停服用例后重新验证。见[末尾报文与停服 B](../optimization/benchmarks/native-udp-terminal-drain-20260921-b/report.json)。
