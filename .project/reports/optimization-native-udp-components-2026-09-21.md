2026-09-21 后续验证：完整框架 C 的启动退出、公共 UDP 结束与真实 UDP 自然结束通过，但暂停预测和最大快照缺口超时失败。暂停问题已用真实 TCP/UDP 强制首帧到达交错复现并修复，53 项回归通过；最大快照四次独立重跑通过，尚未认定根因解决。完整门禁 D 已通过 560 项 C++、781 项 Python、305 个子测试及两个种子的独立 1000 帧回放；失败观察器未捕获事件，仍保留 C 的历史缺口超时。原生共用传输层 ASan 对照显示原实现和候选都可能触发 Ready/空闲超时，候选自动恢复一组通过，启动和帧推进性能仍需处理。详见[当前框架与网络诊断](optimization-framework-lifecycle-2026-09-21.md)。

选择性 ACK 暴露了实际协议缺陷：前面的报文丢失时，后续 ACK 释放了发送缓存，但接收序号窗口尚未前移。旧发送端会继续发送窗口之外的合法后续报文，导致对端关闭。候选把发送序号跨度约束在最早未确认报文之后，收到补齐缺口的 ACK 才继续。首包与中间包丢失的固定对照同时覆盖旧格式和带连接代际的格式，未修改协议、缓存预算或重试上限。

异步字节流同时修正了现代 Asio 执行器的工作保活方式，并保留旧执行器支持。原接收环不足以容纳一次完整乱序窗口，候选采用有界 128 KiB 接收环。实际收包测试曾错误假设写入完成后 available() 必然立即非零；有界 socket 可读等待记录确认了该时序差异，后续 ACK 断言也改为等待并交付真实 ACK。旧失败均保留。

监听器验证修复了缺失的状态成员声明，并要求非法报文确实被处理后再判断无状态变化。当前运行环境的原始 UDP 诊断能收到 1201 字节，未收到 2048 字节及更大报文；实际超限测试因此精确覆盖协议上限 1200 的下一字节，4096 字节交付仍未验证。大数据夹具先前冻结时间、随后又每次只处理一个客户端报文；当前实时传输模式按实际时间维护重传，并有界批量处理已到达报文，十秒期限和全部数据一致性断言不变。G/H 的失败记录继续保留，不能据单次通过声称所有弱网场景已解决。

加载接入 C 的十项正式门禁已结束，八项通过；完整架构回归通过 1,632,030 条断言，输入契约通过 3,074,258 条断言。框架与战术集成失败。战术集成的 ASan 实际服务端首次绑定超时，原期限仍为 30 秒。公共 TCP 传输重构的 Release 七组通过，ASan 实际客户端仍有确认/摘要进度失败，尚未认定根因。

隔离 X11 下的[完整框架重验 B](../optimization/benchmarks/framework-display-20260915-b/report.json)实际执行了原门禁：560 项 C++ 通过，Python 765 项与 305 个子测试通过，三项失败分别是首次输入前关闭窗口、真实 UDP 自然结束确认、公共 UDP 循环中的比赛结束。此前缺少窗口的前置条件已经满足；后续独立进程确定性步骤因 Python 失败未执行。正式门禁不能标为通过。

加载性能仍不达标：最近诊断中 Release 启动阶段 Q 退出为约 272ms；ASan 两个阶段约 703ms / 354ms，部分绑定耗时超过 30 秒。原 250ms 退出目标、Debug 无优化构建和泄漏检查保持不变。训练、目标硬件渲染、50ms p95、长期运行、打包和完整产品弱网等要求仍需完成。

主动连接器已验证数字地址及 localhost 解析、最多八个端点、关联执行器、重复取消和物理 socket 回收；系统 DNS 长时间阻塞时的退出上限仍未验证。

后续依次处理图形退出与比赛结束生命周期、TCP 重构失败定位和启动/退出性能；再接入原生客户端/服务端及完整弱网、回放和正式门禁。组件通过不会手动提升里程碑状态。[证据目录](../optimization/benchmarks/native-udp-components-evidence-20260915-a/archives.json)保存了修改前的任务、计划与报告，旧执行目录、失败日志和摘要保持不变。
