# 加载取消的认证与席位释放 — 2026-09-15

本轮沿里程碑 23 → plan-23.1.1 → task-23.1.1.2 完成私有候选的加载取消协议、服务端席位释放和实际客户端收尾。Release / ASan 的组件检查及六个实际窗口场景证实了有效取消与席位重用。ASan 退出和服务端启动仍超过既有指标；实现尚未正式接入，整体产品质量状态不提升。

## 实现

| 环节 | 原行为与问题 | 当前候选 |
| --- | --- | --- |
| 网络 / 连接所有权 | 客户端退出只关闭连接，服务器仍保留入场租约；其他玩家可能继续等待该加载者 | 增加 LoadCancel 91 / LoadCancelled 92，使用固定 68 字节完整凭证，验证当前连接、席位、比赛标识、代际和秘密值 |
| 服务端状态机 | 连接换代与迟到消息可能交错；开局后释放席位会破坏同局恢复 | 在现有互斥范围内校验并释放尚未开局的当前入场资格；旧代际及其他连接不能释放新所有者；已开局时拒绝取消入场资格并保留原恢复身份 |
| 架构 / 开局屏障 | 终态确认仍在发送时，连接可能暂时留在列表中 | 清除席位、待用输入和 Ready 状态后标记 Cancelled；开局屏障跳过已释放的入场资格，确认仍按现有有界发送队列排空 |
| 客户端 / 手感 | 若等资源回收结束才发送取消，会延后服务器获知退出 | 首个退出检查点即发送取消，让 IO 工作线程在资源展开回收期间处理；取消状态不再发布输入或安排重连 |
| 框架 / 收尾 | 退出前计算成功状态，可能漏掉收尾期间发现的无效确认 | 最多等待从首次请求起算的 100ms，完整校验确认中的所有权；收尾后再读取失败状态，确保无效确认反映到实际进程结果 |

服务器只有在释放成功后才发送有效确认。确认发送失败不会恢复已释放的入场资格。离线、写入失败或确认超时不能证明即时释放，继续依靠现有有界租约；本轮没有声称离线取消已立即到达服务器。秘密值不会写入新增客户端日志。

最终私有组合为 seat B 服务端、seat C 客户端和前轮 retry B 核心。seat C 在 B 的协议及客户端实现上补齐收尾失败结果传播。没有新增核心字段布局变化，本轮正式源码与正式构建产物均未修改。

实现入口：[协议编解码](../optimization/benchmarks/native-loading-seat-20260915-b/overlay/frame_sync/native_recovery_wire.hpp)、[服务器释放与开局屏障](../optimization/benchmarks/native-loading-seat-20260915-b/overlay/frame_sync/engine_tcp_server.hpp)、[客户端取消与确认](../optimization/benchmarks/native-loading-seat-20260915-c/integrated_client.cpp)、[进程退出结果](../optimization/benchmarks/native-loading-seat-20260915-c/overlay/frame_sync/native_client_loop.hpp)。

## 组件与真实客户端检查

两种构建各通过 12 项实际 TCP 取消契约：固定报文边界、前缀/分片、尚未发送加载收据时取消、席位重新分配与旧凭证重放、完成/取消/迟到 Ready 合并到达、连接换代及过期代际、四种外来证明、无身份连接、其他玩家开局和已开局后的拒绝。原有每种构建 11 项加载及恢复回归也通过。

五种收尾场景使用实际 IntegratedFrameSyncClient、真实准备状态 GameEnv 和实际 TCP：有效确认、错误秘密值、错误代际、服务器静默、连接关闭。两种构建共 70 条断言通过，均无比赛推进；只有无效确认产生失败状态。最慢的 100ms 静默收尾分别约 101.279ms 和 100.392ms。这是无图形的收尾契约，不能替代整个图形进程的退出指标。

首次对照的测试预期被实际结果否定：旧服务器收到未知的 91 类型时，原本就会按协议错误撤销该连接的入场资格。A 阶段因此在断言处退出 1，三个子命令均退出 0，原日志保留。后续 B 将“正常关闭”和“显式取消”分别测量，避免混淆：

| 行为 | 旧服务器 | 新服务器 |
| --- | --- | --- |
| 只关闭连接 | 保留租约，新连接分配另一个席位 | 保留同样的恢复语义 |
| 发送 91 取消记录 | 按无效协议处理，错误计数 +1，撤销入场资格 | 验证凭证后正常释放，错误计数不增加，并发送有效确认 |

证据：[新旧行为及两套组件回归](../optimization/benchmarks/native-loading-seat-20260915-b/report.json)、[实际客户端收尾](../optimization/benchmarks/native-loading-seat-20260915-c/report.json)、[首个预期错误的记录](../optimization/benchmarks/native-loading-seat-20260915-a/execution/release-before-witness.log)。

## 实际窗口结果

使用实际产品服务端与客户端、独立 X11 环境、XTEST 的 Q 按键，以及 Linux pidfd 观察自然进程退出。两个测试连接分别持有席位 0、2，并通过正常心跳保持加载；实际图形客户端占用席位 1。退出后的新连接必须重新得到席位 1，并收到更高代际，才算验证释放。没有向这些加载观察者发送 Ready 或推进比赛。

旧客户端仍关闭连接并保留席位租约，因此新连接收到 Busy；新客户端在两个加载阶段均收到有效确认，并让原席位重新分配。全部服务端及客户端退出码为 0，确认比赛帧均为 0，没有 sanitizer 错误。

| 构建与场景 | 退出耗时 | 服务端绑定耗时 | 席位结果 | 原指标结果 |
| --- | ---: | ---: | --- | --- |
| Release / 旧客户端初始加载 | 68.047ms | 0.548s | 租约保留，Busy | 通过 |
| Release / 新客户端初始加载 | 44.218ms | 0.473s | 有效确认，席位 1 可重用 | 通过 |
| Release / 新客户端草皮生成 | 48.290ms | 0.278s | 有效确认，席位 1 可重用 | 通过 |
| ASan / 旧客户端初始加载 | 649.576ms | 25.435s | 租约保留，Busy | 未通过 |
| ASan / 新客户端初始加载 | 894.232ms | 37.031s | 有效确认，席位 1 可重用 | 未通过 |
| ASan / 新客户端草皮生成 | 424.402ms | 43.497s | 有效确认，席位 1 可重用 | 未通过 |

退出标准仍为 250ms，服务端绑定仍为 30s，未放宽阈值。六次测量每场只有一个样本，不证明稳定性能收益或 p95。新客户端两次 ASan 场景虽然成功释放席位，退出仍约 894ms / 424ms，绑定约 37s / 43s；完整窗口报告的 passed 明确为 false。诊断进程退出 0 仅表示测量及回收完成。

证据：[完整窗口结果](../optimization/benchmarks/native-loading-seat-window-20260915-a/report.json)。
