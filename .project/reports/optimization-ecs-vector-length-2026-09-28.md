# ECS 比赛热点与距离计算优化

归属 ms-21.1 → plan-21.1.1 → task-21.1.1.2。固定 11v11 比赛的 2,000 个稳态逻辑帧中，每帧约含 10 次比赛子步骤。独立阶段插桩表明，种子 42/43 的控球统计累计约 1.49/1.57 秒，是测得的最大比赛管线阶段；球员处理约 1.06/1.43 秒。进一步插桩记录约 44 万次球员控球统计和 516 万/534 万次可达性估计。插桩后的两个种子最终哈希均与未插桩基准一致；插桩时间只用于定位，不进入正式性能比值。诊断源文件见 [`ecs_cpu_phase_profile.cpp`](../optimization/diagnostics/ecs_cpu_phase_profile.cpp)，四份原始运行见 `../optimization/evidence/ecs_cpu_{phase,detail}_seed{42,43}_20260928.json.gz`。

先尝试在可达性估计中用平方距离排除明显不在 16/48 米搜索半径内的目标，并在阈值附近保留原始长度比较。再将单处距离计算的三次 `pow(x, 2)` 换成 double 乘法。两轮均通过可达性差分契约和整场状态轨迹，但 15 对正式 CPU 门禁未通过：首轮种子 42/43 的 CPU 95% bootstrap 上界为 1.064/1.017，第二轮为 1.033/1.043；原始失败样本全部保留在同目录的 `ecs_radius_formal_*` 和 `ecs_length_formal_*` 压缩证据中，没有剔除慢样本。

最终把同样的等价平方计算放入 `Vector3::GetLength()`，覆盖控球统计和其他频繁的距离查询，同时保留 double 求和、double 平方根、float 转换和小距离归零顺序。`std::pow(float, 2)` 的 float 参数转为 double；float 至多有 24 位有效位，其平方可由 double 精确表示。216,640 组冻结参考差分用例、1,555,846 项断言、16/48 米阈值相邻浮点数、两个种子的整场最终哈希均通过；完整状态检查点由正式门禁逐对核对。

正式门禁采用仓库内版本化基线 `ecs_v2.json`，两种子各 15 对未插桩、交错顺序的进程，共 60 次比赛运行，1,590,027 项断言、零跳过。种子 42 的 CPU 几何比为 **0.8636**、95% 区间上界 **0.8995**，墙钟几何比 **0.8635**、配对 p99 中位比 **0.8721**；种子 43 依次为 **0.8052**、**0.8163**、**0.8052**、**0.8498**。两种子的候选版整场分配次数/字节数分别从 656,253/68,421,236 降至 482,054/47,130,528，以及从 674,471/75,299,113 降至 492,607/53,904,593；基线与候选版的 `full_cache` 分配均为零。所有输入、预热、状态检查点、最终哈希和活跃标志一致。此次完整比较判定 `passed=true`，无失败项。

可重跑命令：`python3 .project/checks/ecs_performance.py --cpu 0`。完整摘要、逐帧原始数据、机器信息、编译参数及失败/成功历史分别见 `../optimization/evidence/ecs_vector_length_formal_20260928_comparison.json.gz`、`ecs_vector_length_formal_20260928_log.txt.gz`、`ecs_radius_formal_*`、`ecs_length_formal_*`。最终源码上的项目质量编排器已经重新执行框架、架构、性能及依赖门禁，`ms-21.1` 状态为 `verified`。
