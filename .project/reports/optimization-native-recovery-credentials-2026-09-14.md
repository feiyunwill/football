# 原生重连：凭证与连接所有权组件（2026-09-14）

归属：ms-23.1 → [plan-23.1.1](../plans/plan-23.1.1.md) → [task-23.1.1.2](../tasks/task-23.1.1.2.md)。

已实现并验证独立的恢复凭证组件，尚未接入实际产品协议。Release 和 ASan/UBSan 各通过 7 组检查、9,274 条断言、1,000 次连续恢复；零跳过，开启泄漏检测。每场比赛固定占用 1,992 字节，最多 22 个槽位。见[候选实现](../optimization/benchmarks/native-recovery-credentials-20260914-b/native_recovery_credentials.hpp)、[测试](../optimization/benchmarks/native-recovery-credentials-20260914-b/contract.cpp)和[结果](../optimization/benchmarks/native-recovery-credentials-20260914-b/report.json)。

组件使用每场独立的 128 位比赛标识、每槽位 256 位凭证和 64 位连接代次。正式默认入口直接调用 Linux getrandom，单次最多请求 32 字节，使用 GRND_NONBLOCK；短读或错误立即失败并清空输出，不采用比赛 seed、计数器或其他随机源作为后备。这遵循 [Linux getrandom 接口语义](https://man7.org/linux/man-pages/man2/getrandom.2.html)。本实现仅验证当前 Linux/WSL 环境，其他系统不伪造成功。凭证不进入比赛 RNG 或确定性状态。

| 操作 | 实际行为 |
|---|---|
| 首次入场 | 为未使用槽位发放独立凭证，记录唯一连接代次 |
| 有效恢复请求 | 核对比赛、槽位及凭证；切换代次，旧连接回调失去所有权 |
| 回复丢失后重试 | 保留同一个待确认凭证；旧凭证与已收到的新凭证都可继续同一次恢复 |
| Ready 确认 | 必须证明收到了新凭证；提交轮换并废除旧凭证；重复同代次 Ready 幂等成功 |
| 断线或恢复中断 | 保持最初的离线期限，重复请求或重复关闭不延长宽限期 |
| 到期或显式撤销 | 清除凭证并拒绝恢复；已到期槽位不自动当成新玩家重新分配 |

宽限期默认 30 秒，可在 1 毫秒至 5 分钟之间配置；这是组件约束，最终产品弱网验收预算尚未据此调整。表由调用方在会话所有权锁内串行使用，组件本身不驱动游戏引擎、发包或选择球员输入。

测试覆盖 256 个凭证单比特篡改、128 个比赛标识单比特篡改、错误槽位、零凭证、无效容量、无效时间、时钟倒退及截止时间溢出。恢复用例覆盖旧连接关闭、旧 Ready、旧清理回调、回复丢失、已收到新凭证后的再次断线、重复 Ready、连续轮换、过期边界以及另一玩家所有权保持不变。真实 getrandom 调用另有集成检查；短读、EINTR、EAGAIN、ENOSYS 通过链接级系统调用包装注入，均未触发无限重试。真实随机值采样仅用于接口冒烟，不作为密码安全证明。

首轮私有候选在 -O3 -Wall -Wextra -Wpedantic -Werror 下编译失败：编译器不能据构造时的配置校验证明极大槽位索引不越界。第二轮增加对物理数组上限的显式校验，保留配置上限和极大索引测试，不放宽编译选项。首轮源码、失败命令及日志保留在 credentials-a。

接入任务继续按以下顺序自动执行：

1. 将原生四个客户端/服务器目标纳入完整构建覆盖，刷新此前遗漏的 ASan TCP 客户端；旧产物和源文件先归档。
2. 增加明确版本和能力边界的原生恢复握手。保持 FNAT1 比赛及历史回放含义不变，不复用旧 MakeSessionToken 语义。
3. 服务器在有效请求后认领原槽位，清除该槽位旧连接预排输入，AI 在恢复完成前继续接管；在帧边界完成手动输入交还。每个延迟回调核对连接代次。
4. 传输带有明确“下一权威帧”语义的有界完整快照，UDP 按数据包容量分片并限流；验证完整性、重复片、过期传输和慢接收者隔离，再恢复并追帧。
5. 实际客户端以有限重试循环恢复连接，重置发布时钟、输入历史、预测与渲染状态；回放明确记录恢复检查点及缺失区间，不伪造掉线期间输入。
6. 运行两个实际客户端、双方槽位、反复断网、错误/过期/跨场凭证、延迟和丢包组合，核对所有权、AI 交还、状态哈希、输入手感和退出清理。恢复凭证的传输认证与加密也需单独验收。

当前没有新的产品网络恢复能力，也未声称解决传输机密性。原生产品断线现状见[实际断线基线](optimization-native-reconnect-baseline-2026-09-14.md)。network_reconnect 及产品级状态保持未通过。
