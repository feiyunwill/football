# 统一原生输入缓冲预检

2026-09-13。对应 ms-22.1 → plan-22.1.1 → task-22.1.1.1。共享 C++ 输入缓冲已实现并通过差分预检，目前保存在独立实施目录，尚未接入三个游戏入口，正式输入门禁仍未完成。

[NativeInputBuffer 实现](../optimization/benchmarks/native-input-buffer-20260913-b/native_input_buffer.hpp)将最新方向、持续按钮、键盘和手柄的短按缓存放在同一处。应用只在接收一个新逻辑帧输入时调用 `Take()`；普通轮询只更新物理状态。缓冲保留全部同时按键，统一数字方向、手柄方向键及径向死区；失焦或断连清除对应输入。暂停及恢复切换清空待提交动作，恢复后要求一次物理中立状态观察，避免暂停前持续按键直接触发新动作。

本次直接使用当前 [Python InputBuffer](../../gfootball/frame_sync/graphical_input.py)产生固定操作及期望结果，不另写一份模拟实现作为参考。测试序列包含 20,168 次操作：5,574 次输入观察、6,022 次逻辑输入提取、2,816 次命令提取、722 次暂停／恢复、5,014 次状态检查，以及构造和关闭。覆盖所有现有键盘与手柄映射、短按只保留一次、持续／释放、相反方向抵消、数字方向优先、轴死区、失焦、断连、恢复屏障、非法轴与键名的事务拒绝，以及关闭后的行为。

[差分报告](../optimization/benchmarks/native-input-buffer-20260913-b/evidence/report.json)已以退出码 0 终止，SHA256 为 `95c12f84dc7e07573511fdc41f7ae76debd6514ee250bfa4532ee1e436a92da4`。Release 与 ASan/UBSan 各通过 92,699 条断言、零跳过。两个方向分量按序列化后的 float32 位逐项比较，按钮位掩码和命令状态精确比较。

最初 A 批次遇到类定义未完成时的局部 `constexpr` 求值编译错误。B 修正该声明位置限制后通过；未改变参考数据。原始 Python 操作文件 SHA256 固定为 `b3d333d397d2f59938622a3fa2f299ae299b87b1aac5371e412d0ae29de10d2d`，两个批次逐字节一致，A 的源码、编译错误和退出码已保留。[独立核验收据](../optimization/benchmarks/native-input-buffer-20260913-b/verification.json)校验 28 个文件，SHA256 为 `b728cea3a8cbc10d4d5299259d73fb92490905dc8edf1a4a90cb64d189c19278`。通过版本的头文件 SHA256 为 `2083c5bc5e2588386267cd12ee516f3dfc32271e034540695b6214b3e6c240c0`。

这些构建和测试在正式架构正确性检查结束前完成，未改动正式性能链冻结的引擎、入口或检查文件。此前[实际 SDL/X11 采样预检](optimization-native-input-sampler-2026-09-13.md)已验证物理事件入口；本次验证的是采样与逻辑帧之间的状态转换，尚无游戏入口接通或实际球员延迟的结论。

接下来将此缓冲接入本地、TCP 和 UDP 入口，替换各自重复的键盘映射。本地入口改为提交完整 `SlotInput`；联机入口需在处理权威追帧后，以实际帧号取得并缓存本地输入，使等待、重传及预测使用同一份数据。然后执行真实 GameEnv 的方向／粘性按钮释放、同时输入和暂停恢复验证，再推进固定节拍与球员响应延迟验收。
