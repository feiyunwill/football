# 原生持续输入与网络工作线程

本轮按 ms22 输入与操作手感 → plan22.1.1 输入与节拍 → task22.1.1.1／task22.1.1.2 推进，同时关联 task22.1.2.1 和 task23.1.1.1。当前修复了已复现的持续输入空档；产品级采样、释放和动作响应延迟仍未通过，质量状态不手动提升。

## 问题与实施

上一轮本地固定步长及客户端追帧修复后，主线程绘制时仍停止收包和输入发布。持续按住方向和冲刺的中央区间，TCP 70 帧中有 42 个空输入，UDP 71 帧中有 43 个空输入。

本轮新增 NativeTransportPump，以 4ms 绝对周期调度网络工作；它在主循环作用域内创建，停止或异常退出时先唤醒并 join，然后才销毁窗口输入和客户端。工作线程不调用 SDL 或 GameEnv。主线程仍可在合适的时机协助轮询／发布，poll_mu_ 保证 IO context 的 restart、回调分发及 close 不并发执行。

NativeSharedInputBuffer 加锁保存 SDL 主线程采样结果；原有 NativeInputBuffer 的方向、死区、按下、保持、释放和恢复屏障算法继续使用。NativePublishedHistory 将已发送输入历史与预测边界一起保护，工作线程读取发布的边界，不读取 FrameSimulation。重复的帧目标只采样／提交一次；预测读取实际提交值。历史仍只有原来的一份固定容量存储。

TCP 的运行／失败状态、UDP 的失败状态及心跳读取的当前帧改为原子值。接收回调只操作受保护的收件状态，比赛状态、预测、重放和绘制继续由原有主线程处理。

## 实际测量

独立的[渲染分段测时](../optimization/benchmarks/native-render-profile-20260913-a/report.json)在原有 1280×720 软件 OpenGL 窗口执行，三个程序都通过实际操作。进行中区间内，完整绘制平均约 52–76ms，准备姿态约 1.7–2.6ms，像素读回加呈现约 5–7ms，其中窗口交换约 0.6ms。观察器不改变输入、状态或渲染调用。读回是优化候选，但这些测量不支持把它视为主要开销。

[首次严格窗口复测](../optimization/benchmarks/native-input-pump-windows-20260913-a/report.json)中，TCP 69 个、UDP 68 个持续输入权威帧全部完整。随后把进行中等待、持续输入、失焦、暂停／恢复和释放检查纳入固定 input_contract，并在最终 D 轮重新执行：

| 最终 D 实际窗口 | 本地 | TCP | UDP |
| --- | ---: | ---: | ---: |
| 实际 Step 调用 | 443 | 513 | 513 |
| 渲染／呈现次数 | 89 | 127 | 117 |
| 确认回放帧 | — | 512 | 512 |
| 持续输入中央区间权威帧 | — | 70 | 69 |
| 其中空输入 | — | 0 | 0 |
| 首次输入进入客户端 Step 完成 | 85.39ms | 150.92ms | 178.34ms |

全部实际窗口、两台服务器均正常退出，每次比赛渲染恰好呈现一次，渲染前后逻辑哈希一致。中途保存的 475／471 帧前缀与最终回放相同。

失焦、控制暂停、恢复时仍保持按键、以及真正释放后重新按下均以服务器的实际输入检查。每个清理区间排除了转换后的前 300ms，因此它验证清理最终生效，不等同于 50ms 释放延迟验收。网络窗口中的暂停是控制输入暂停，不能据此声称实现全局权威暂停。

上表是每个程序单次物理按键观测，不是多相位延迟 p95，不是球员响应的因果对照。持续输入已经连贯，但首次响应仍慢。D 中 TCP 的一次约 20ms 物理射门短按对应 4 个连续的射门输入位帧，UDP 对应 1 帧；这不是四次射门事件，说明快照保持和采样时刻仍会影响短按持续时间，必须继续处理。

## 固定验收入口

最终 [D input_contract](../optimization/benchmarks/native-input-pump-20260913-d/gate/report.json)通过 2,584,154 条断言、零跳过。报告 SHA256：cbb7d3de44b1ef4d0eaf3bfba3036569ac190bd00270a2dae48060f0a7ea1815。

新增并发契约已成为固定 CMake 测试目标和输入检查器的必跑项，在 Release、ASan／UBSan 以及单独的 ThreadSanitizer 构建中各通过 20,333 条断言：

- 独立账本验证 4,000 帧的唯一采样／发送、预测读取和容量边界。
- 主线程不执行收发时，通过受控交错连续发布 128 帧，并验证保持、释放和待消费短按。
- 64 次作用域生命周期均完成 join，覆盖异常传回、禁用模式和重复停止。

ThreadSanitizer 覆盖共享输入、发布历史和工作线程组件，并不代表整个原生引擎或两个图形客户端已全部接受线程检测。实际产品窗口运行 Release 程序；完整物理／输入契约与全部 1,024 个确认帧的逐帧回放在 Release 和 ASan／UBSan 引擎中验证，两个构建的时钟／重放检查各 452,537 条断言。

当前代码还完成了[旧 TCP 兼容回归](../optimization/benchmarks/native-input-pump-20260913-d/legacy-report.json)：Release 与 ASan／UBSan 各 40 帧、8 个哈希，包含重连快照和慢旁观者。这属于旧通用接口，不表示 FNAT1 产品入口新增了重连或旁观能力。

第一次 A 构建因测试样本类型缺少命名空间失败；B 编译成功，但夹具默认失焦导致预期不符；C 修正夹具后通过三种检测和原有完整输入门禁；D 将严格进行中和线程检查加入永久门禁。各失败退出、旧源文件、构建日志均保留。没有修改原始性能基准、默认场景、AI 对照或产品质量阈值；窗口工具的执行超时随新增的有界进行中／焦点场景调整，不用于降低响应目标。
