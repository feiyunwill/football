## 发现及修改

旧观察历史虽然最多保留 100 步，但每步可以引用任意大小的可变对象、NumPy 底层数组和不断增长的附加帧/调试列表。一个很小的数组视图也可能保留整块大数组。关闭视频时直接改写传入 trace；保存 pickle 时临时删除共享 frame、插入 config，遇到异常可能无法恢复。

新增 `gfootball/recording_buffers.py`。输入经过数量、深度、类型和字节检查后复制为独立的不可变观察状态；数值数组拥有紧凑、只读的 bytes 底层，剥离外部大数组和 dtype metadata。数组头的形状/类型赋值也受到保护。映射、序列和动作记录不可变；未知对象、对象数组、循环引用及超限数据明确拒绝。序列化创建独立字典，恢复普通 ndarray 视图及注册的 CoreAction 类型；不会修改源观察。

`ObservationHistory` 按数量和累计字节淘汰最旧状态，单步附加帧/调试文本也受独立上限和整步预算约束。附加缓存变更通过历史锁同步更新字节账目；读者继续持有已经淘汰的状态时，其后续缓存变化不会影响当前历史。单条无效输入不会替换之前有效的历史。

新增 `gfootball/recording_output.py`。每次录制开始前预留 dump/video 的完整允许空间和文件数量，同时扫描平面输出目录的已有文件，防止顺序重建处理器清零磁盘账目。达到配额时拒绝新录制，不删除旧文件。

pickle 直接写入具有字节检查的流，不先生成整个文件的字节串；短写会继续，零进展或 I/O 错误会中止。视频检查编码器是否打开，文件描述符在 OpenCV 打开路径前关闭。每次编码和 release 后检查文件大小，另限制步数、视频帧数及并发录制数。

输出先写到当前目录下独占创建的临时文件，显式 finalize 后使用同文件系统硬链接发布，目标存在就报错。两个目标中第二个冲突时撤销本次已经建立的第一个链接，保留用户原文件。finalize 可重复调用；成功文件移交给用户后，abort 和析构都不会删除它们。失败/未显式结束的录制中止并清理自有临时文件，清理前核对文件身份；删除失败可再次尝试，原始错误不会被清理错误覆盖。

低质量视频缩放现在同时约束宽、高并保留比例，输出尺寸取偶数，避免旧的元组比较只比较第一维，以及编码器隐式裁掉奇数行列。

## 环境入口接入

`gfootball/env/observation_processor.py` 使用新的观察历史及输出对象，保留既有统计叠字和绘图逻辑。公共 dump 名限制长度、路径字符和名称数量；开始录制及历史预填充成功后才扣减尝试次数。`steps_before=0` 现在确实表示没有历史预填充。

处理器增加显式 close，reset 在替换历史前结束旧录制。一个输出在 update/add_frame 中失败时中止其他活动输出并关闭录制器。批量结束会继续清理剩余录制，并返回原始失败；错误不会留下一个永远被认为仍在进行的 dump。

`football_env_core.py` 的 reset/close/正常比赛结束显式管理录制器；close 的 I/O 错误仍会释放引擎。整场录制移到首条 trace 写入前启动，保留第一个动作与 frame 0，也避免一帧就结束时删除 trace 后再次启动录制。析构中止未显式结束的输出。`ScriptHelpers.dump_to_video()` 成功时显式关闭并返回文件信息，失败时中止。

这些环境入口改动目前是**源码审查与语法验证结果**。没有通过替换 native 模块或复制类体制造入口测试通过。`test_recording_environment.py` 已准备 7 项真实 Config/CoreAction/ObservationProcessor 测试，但本机缺少 absl、six、Gym 和可运行的 Linux 引擎环境，因此尚未执行。实际 GameEnv 首帧/单步终局/重置/回放及真实叠字路径仍需原生验证。

## 默认预算及边界

| 对象 | 默认预算 | 达到上限时 |
| --- | --- | --- |
| 观察历史 | 100 步、256 MiB | 淘汰最旧观察 |
| 单步、debug 子树、单张 RGB 图像 | 32 MiB、1 MiB、16 MiB | 拒绝超限输入 |
| 每步附加画面 | 16 张、16 MiB | 在整步预算内淘汰最旧附加帧 |
| 每步调试文本 | 64 行、64 KiB；每行 4 KiB | 淘汰旧文本或拒绝超长单行 |
| 结构、字符串、dump 名称 | 8192 节点、16 层、64 KiB 字符串、32 个名称 | 拒绝超限 |
| 单次 dump、video | 128 MiB、512 MiB | 中止本次未发布输出 |
| 平面目录输出预留 | 4 GiB、256 个文件 | 拒绝新录制 |
| 活动录制、每次步数、每次视频帧数 | 4、10000、100000 | 拒绝或中止 |
| 目录扫描 | 4096 个直接子项 | 拒绝继续扫描/录制 |

观察字节计入实际数组头、bytes、映射、序列和缓存 deque/条目，重复引用保守地重复计入。少量固定控制对象和适配器另受数量限制。外部读者保留的淘汰状态、调用方数据、pickle 暂存、NumPy 临时值、原生引擎、GPU 和 RSS 不属于该数字。

目录预留在**共享同一个 OutputBudget 的生产者**之间协调。已有直接普通文件会计入下一次预留；子目录内容、其他进程，以及同目录但使用独立 budget 的并行处理器不在此协调范围，后者仍需共享注册/进程协调设计。当前代码未宣称这是整个磁盘的全局硬配额。

OpenCV 内部缓冲和单次 write/release 产生的临时超量只能事后检测；超限不会发布为成功文件，但没有证明临时文件任何时刻都低于阈值。文件发布依赖硬链接支持，失败时明确报错；两个文件没有成组原子提交，未声称断电持久性。pickle 仍只用于可信的本地回放数据，未变成不可信文件解析器。
