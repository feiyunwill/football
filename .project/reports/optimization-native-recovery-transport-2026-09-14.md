## 凭证、分片与快照候选

凭证表使用系统熵、比赛标识、原槽位及 256 位凭证，轮换凭证与连接代次隔离迟到回调。增加了赛前最终释放与开赛封闭入场接口；已验证旧清理回调不能释放新主人、过期赛前槽位可重新分配、开赛后不能占用空槽。两种构建各 8 项检查、9296 条断言、1000 次恢复循环；每场固定控制状态 2000 字节。

FNRC/1 是独立版本的恢复信封，内部保留 FNAT/1 比赛描述符。8 类报文采用明确的小端布局，最大实际报文 1046 字节，快照上限 1MiB，每片 1024 字节。收全后对整个快照做 SHA-256 校验；发送每轮最多四包，并可在容量不足时原片重试。解析覆盖 TCP 分包、合包、畸形输入、独立 Python 字节预期、乱序和重复分片、超时及摘要失败。

组件合计 45054 条断言通过：两种构建各有 19566 条报文/传输断言，并各在两份独立 GameEnv 中完成 8 次快照恢复、680 帧逐帧追平。凭证和传输组件均仍是候选文件；SHA-256 与明文凭证并不提供传输加密或服务端身份认证。OpenSSL 只使用本机现有库，尚未修改正式 CMake 依赖。

证据：[凭证生命周期](../optimization/benchmarks/native-recovery-credentials-20260914-c/report.json)、[报文和真实引擎传输](../optimization/benchmarks/native-recovery-wire-20260914-b/report.json)、[接入约束](../optimization/benchmarks/native-recovery-wire-20260914-b/INTEGRATION.md)。

## 现有 TCP 服务端的具体候选实现

候选直接修改现有 EngineTCPServer，并用现有 integrated_server.cpp 产品入口编译、启动独立服务端进程。正式路径尚未替换。主要实现：

- 在会话锁内发行或轮换凭证，保留原槽位；转移代次后关闭旧连接并清理其未提交输入，旧关闭回调不能清掉新连接的输入。
- 赛前短暂断网保留原宽限期；比赛开始封闭新入场。Ready 只在 IO 线程入队，由帧线程取得状态哈希并验证、提交和交还控制权。
- 在 next_frame 之前保存引擎状态，连续广播之后的真实权威帧。恢复期间由 AI 继续控制，交还通知与 Accepted 使用同一个帧边界。
- 快照片让出权威帧、哈希、心跳和全部槽位通知的发送容量；恢复后缀设 1024 帧上限。快照失败或慢接收者只影响对应会话。
- FNRC 与旧 FNAT/legacy 分支明确识别；旧 Ready 不能被解释为恢复证明。

两种构建各完成 7 次实际网络恢复、428 个连续权威帧、7 份快照。覆盖赛前掉线、双方槽位、反复掉线、无效和跨比赛凭证、存活连接的替换、Ready 后立刻断线、重复 Ready 与 AI 交还。恢复后实际输入检查通过。这里使用独立 Python 协议端，不是两个原生产品客户端。

两组实际网络记录均在 Release 与 ASan 的独立 GameEnv 中复验，合计四次运行；每次验证 428 个权威帧、7 份快照及 1396 个快照后续帧，5624 条断言通过。每个后续帧均与从比赛初始状态重放得到的哈希比较。

补充生命周期复核已完成：两种构建各 5 项真实 TCP 检查，分别 194/187 条断言，验证赛前过期释放、非法 Ready 释放、开赛后凭证过期、反复请求不延长原宽限期、1MiB 慢传输及超限快照仅影响对应会话。所有引擎回调强制检查帧线程归属。这组使用可控回调，不冒充真实 GameEnv；另外原 legacy 真实引擎测试在两种构建各通过 40 帧、8 个状态哈希和 87132 字节重连快照，分别 2827/4229 条断言。见[生命周期与旧协议结果](../optimization/benchmarks/native-recovery-tcp-lifecycle-20260914-b/lifecycle-report.json)。

首次生命周期测试夹具因默认构造函数歧义编译失败，已在独立后继阶段修复并保留原失败日志；候选服务端实现未因此改动。此前报文测试的首轮编译失败也保持归档。尚不将这些组件成绩视为原生产品重连完成。
