## 实现

原 `OutputBudget` 只对自身实例加锁。两个处理器即使指向同一目录，也可能同时看到足够空间，再分别预留同一份容量。

新增 `gfootball/recording_directory.py`。目录使用一个短期操作锁和最多 16 个活动预留槽。每个槽有独立 OS 锁及有界 JSON 记录，记录预留字节、文件数、目录策略和自有临时文件身份。Windows 使用实际 `msvcrt.locking`，POSIX 分支使用 `flock`；本轮实际运行的是 Windows 分支。

每次申请都在目录锁下检查其他仍持有 OS 锁的槽，再计入目录已有文件，最后预留本次完整额度。活动文件已经包含在预留中，核对身份后不重复计费。独立实例通过进程内弱引用注册表共享线程锁；独立进程通过同一组 OS 锁协调。路径别名未被进程内注册表合并时，文件系统锁仍然生效。

同目录活动写入者的 `total_bytes`、`total_files`、`active_dumps`、`scan_entries` 必须一致，否则明确拒绝；单文件允许大小可以不同。活动预留全部结束后可使用新的目录策略，已有文件仍计入。目录锁竞争设置 2 秒获取期限；它不构成对底层文件系统调用的硬实时保证。

进程退出会由操作系统释放槽锁。后续申请可以复用该槽，无需猜测 PID 是否复用或等待某个租约时间。崩溃留下的 payload 文件保留并继续计入容量，不自动删除未知产物。过大、损坏或不符合格式的活动元数据会阻止新申请；已经没有活锁的旧槽可重新写入新预留。

隐藏控制目录 `.football-recording-v1` 保持存在以维持锁文件身份，最多 33 个控制文件、每个最多 4096 字节，另行有界而不计入 payload 配额。未知控制目录内容保留并拒绝使用；不会递归清理用户目录。

`RecordingOutput` 的文件发布、临时文件删除与目录扫描使用同一个操作锁，避免扫描到提交中的半组文件。锁顺序统一为输出对象、预算对象、目录，避免写入错误与 finalize 并发时死锁。即使目录锁无法取得，abort 仍关闭编码器/流并释放预留；留下的自有文件可在后续显式清理时重试。

直接获取的预留也是拥有型句柄，最后一个引用释放后会归还槽。构造失败时先解除半成品对象的句柄所有权，再关闭描述符，避免异常 traceback 长期保留该对象后，析构误关已经被他处复用的描述符。POSIX fork 后关闭子进程继承的锁描述符副本，旧预算/输出对象拒绝在子进程继续使用；该 fork 路径仍待 Linux 实测。

- 实际跨进程策略冲突、OS 操作锁竞争超时与释放后的恢复；没有使用假锁替代成功路径。
- 16 个槽全部占用、17 个拒绝、指定空槽复用，以及控制文件数量/大小限制。

- 发布期间另一线程的申请等待目录事务结束，再根据已提交文件拒绝；写入错误与 finalize 同时发生时两个线程均能结束。
- 目录锁失败也能关闭真实文件流、归还槽；延迟清理和半成品句柄复用有独立回归检查。

## 限制与后续发现

本轮没有执行 POSIX flock/fork、网络文件系统锁、GameEnv、GPU 或 Linux 正式门禁。7 项实际 Config/CoreAction/ObservationProcessor 入口测试仍待原环境可用后执行；当前只调整了它们对控制目录的断言并编译源码，没有替换 native 模块或宣称通过。

目录保证适用于遵守同一预留协议的生产者。其他程序直接写目录、子目录内容、编码器内部缓存/单次临时超量，以及 dump/video 成组原子提交仍在保证范围之外。硬链接发布的文件系统要求保持不变。

唯一新 WSL 健康探测 `2663af9aec7f4f658d84383c849e0000` 的直接 `/usr/bin/true` 超过 12 秒；只停止自有 PID 25036，匹配子进程 0。没有重启发行版、VM 或服务，没有 C++ 修改/编译、Git 操作或绕过 Windows 正式验收限制。其余本地代码和验证工作可继续，整体目标保持 active。

本轮还直接审查了索引排除目录中的 `ScriptHelpers`、实际 replay Player、PlayerBase、FootballEnv 生命周期和已有脚本测试：

- `load_dump()` 全量读成列表，每个回放球员再加载一整份文件；末尾截断引发的 EOFError 也被当作正常结束。
- `dump_to_txt()` 提前截断目标文件，又生成完整列表的字符串，读失败也可能已经破坏原输出。
- 帧率展开把 `physics_steps_per_frame` 当成 FPS。100 Hz 物理、每观察 20 个物理步实际上是 5 FPS，提升到 10 FPS 应插入一个空动作步，旧实现却拒绝；60 FPS 被接受后又向下取整物理步，实际可能变成 100 FPS。
- `replay()` 全量展开、修改传入 config_update、缺少完整 finally 关闭/删除临时文件；Player 在文件耗尽时直接 `exit(0)`，reset 没有重置回放位置，FootballEnv.close 目前只关闭核心环境。
