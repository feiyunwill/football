本轮将 Python 同步和 asyncio TCP 客户端迁移到共享的有界解析层，并在 Windows Python 3.14.6 上通过 32 项检查。`memory_budget.ready=false`。WSL 仍无法启动新命令，Linux 正式验收尚未重跑；这些结果也不包含 GameEnv 模拟、网络预测延迟或长期内存增长验收。

## 实现

新增 `gfootball/frame_sync/client_buffers.py`，负责握手状态、严格协议解析、权威帧、哈希与时间戳预算，两个传输实现共用这一层。

| 保留内容 | 默认上限 | 超限处理 |
| --- | --- | --- |
| 接收 bytes 对象 | 8192 字节 | 关闭会话并清理 |
| 权威帧 | 1024 项 / 512 KiB | 关闭会话，不丢帧后继续预测 |
| 待验证哈希 | 1024 项 | 关闭会话 |
| 输入发送时间戳 | 1024 项 | 淘汰最旧诊断样本 |
| 时间样本 | 50 项 | 有界滚动更新 |
| 待发消息，含活动发送 | 256 项 / 2 MiB | 关闭会话并取消收发 |

接收和负载预算使用 `sys.getsizeof(bytes)`，计入 Python bytes 对象头；权威队列保留原始完整包，消费时才向调用者交付解码列表。容器节点、索引和诊断记录由数量上限约束。表中不是整个进程、Python 分配器、内核缓冲或调用者持有对象的 RSS 上限，临时解码对象也不等同于队列保留负载。

握手必须收到完整 SessionStart 和 SlotAssignment，验证双方人数各不超过 11、总数 1–22、槽位数量、唯一性和范围。权威帧要求连续完整帧及有效输入；未知消息、未协商的快照/增量包、非法大长度、NaN、错序及冲突哈希明确失败。心跳、托管和归还通知按完整消息消费。验证某帧哈希时保留其他帧的记录，避免旧版本弹出不匹配哈希后直接忽略。

默认连接、握手及写入期限各 5 秒，等待宿主 Ready 最多 30 秒，正常传输 3 秒没有完整消息进展则关闭。半包字节不会刷新进展时间。同步客户端的操作系统 DNS 解析仍同步；不能将 socket timeout 说成覆盖所有 DNS 阻塞。输入发送到权威帧返回的时间样本使用 monotonic 时钟，包含排队和服务端处理，并非独立测得的纯网络 RTT。

`client_tcp.py` 用一个非阻塞 select 工作线程完成收发，替代同步 sendall 和无界接收线程。发送先计入预算，部分发送保留同一包；失败立即关闭 socket 并标记状态。显式 close 在状态锁之外等待线程结束，连接建立过程使用代次校验，关闭能打断正在等待的握手，旧连接不会替换新会话。重复连接前完成旧线程清理。

`client_tcp_async.py` 使用原始非阻塞 socket，每个连接固定一个读取任务、一个写入任务和一个期限检查任务。发送负载在调度事件循环前入账；跨线程突发发送至多排队一次写唤醒和一次关闭回调，不再逐包创建任务。活动发送在取消完成前仍计入预算。`close()` 发起关闭，`await close_async()` 完成 IO 取消和活动负载释放；并发 connect 会被拒绝，已有连接的取消完成后才建立下一次连接。事件循环归属明确，外部线程可以发送或发起关闭。

旧 `client.py`、`client_async.py` 的公开类名保留，分别导出新实现。握手方式显式选择：同步默认 `versioned`，匹配 Python 同步服务端；异步默认 `server_first`，保持既有 Python asyncio 服务端的行为；`native` 发送 Connect，匹配现有 C++ TCP 服务端的握手。三种模式的包顺序均经过真实 socket 测试，没有依赖猜测或超时后换协议。异步客户端也补齐了逻辑循环调用的时间样本 API。

ClientLogicLoop 增加终止检查：在已有连接失败，以及发送/期限检查刚触发失败时，停止逻辑循环和预测，不再保存额外快照。其原有单快照回滚和历史确认算法尚待后续完整重构，本轮没有把这一停止保护记为预测算法验收。

## 验证

[当前完整结果](../optimization/benchmarks/python-tcp-client-windows-20260909-final2/report.json)为 32/32 通过：共享缓冲 7 项、同步传输及逻辑停止 13 项、异步传输 12 项，无跳过、资源警告、遗留工作线程、未取回任务异常或悬挂任务告警。异步测试在清理时直接核对属于客户端的任务已经结束、活动发送已释放。

- 权威缓存填满、拒绝、消费释放、再次填充；对象实际字节计账；提前拒绝非法帧头；完整控制消息和后续权威帧分帧；哈希数量及冲突验证；1000 次诊断时间戳写入保持上限。
- 真实 TCP 同步/异步连接，22 槽位完整 271 字节输入包及 227 字节权威包；不同槽位输入保持不变；Ready 由宿主明确发送；分片 SessionStart 不会提前完成连接。
- EOF、坏帧、半包期限、完整消息空闲期限、哈希不一致、输入生成器数量过大均有确定结果。实际 TCP 故障后调用逻辑循环 20 次，验证没有保存、恢复或推进引擎的调用；该检查使用调用哨兵，不伪装为 GameEnv 行为测试。
- 同步重复连接 12 轮、异步 10 轮，分别确认旧线程、旧任务结束及历史释放；宿主输入回调关闭；在握手期间显式关闭及取消调用者任务；并发连接拒绝。
- 跨线程连续调用 1000 次发送，在事件循环暂停调度时仍只有 2 次成功入队，写唤醒加关闭调度不超过 2 次。真实慢接收端配合小 socket 缓冲触发写入期限，活动消息、待发字节和任务数始终受约束。

## 保留的失败记录

所有早期结果均保留在 `python-tcp-client-windows-20260909-*` 目录，没有覆盖失败证据。

- `a`：分片握手测试刚将 Ready 入队就关闭连接，却要求对端已经收包。改为等待真实接收确认，关闭本身仍取消未发送消息。
- `b`：实际关闭路径与 connect 共用整个生命周期锁，关闭等了 2 秒握手期限才返回。修复锁范围和连接代次校验后，关闭可以立即取消握手；原 0.5 秒检查阈值保持不变。
- `d`、`e`：异步关闭一度将错误握手误报为调用者取消，且直接关闭带未完成读取的 Windows socket 会重置对端。分别保留原始连接错误，以及在正常清理中执行 shutdown。调用者取消与尚未完成的系统连接操作竞争时，RST 也是有效断开结果；另加已经实际读到半包后的取消测试，仍要求对端收到 EOF，避免模糊覆盖范围。
- `f`：异步慢端测试一次 sleep 只发一包，在某次 Windows 定时调度下 3 秒内未填满内核窗口，未触发超时。改为维持最多 32 条待发压力，保持同样的写期限和容量上限，避免用定时器粒度决定是否真正施加压力。
- `g`、`final` 的 31 项检查通过后，又发现逻辑循环没有检查新的终止状态，补上保护和实际故障调用检查；当前 `final2` 为 32 项。旧通过结果是对应源码版本的历史证据。
