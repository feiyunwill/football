# 原生客户端恢复、渲染状态和线程资源复核（2026-09-14）

对应里程碑 23 → 计划 23.1.1「传输与恢复」→ 任务 23.1.1.2「断线与重连」。本轮完成可执行的原生 TCP 客户端恢复候选，并通过真实客户端、键盘窗口及独立引擎回放验证。当前客户端 G、草皮随机源修复 P 和 SDL 工作线程清理均位于私有候选目录，尚未接入正式源码及全部七个产品入口。任务、network_reconnect 和产品级质量状态不提升。

正式工程仍是上一轮服务端接入后的 1073 个源码文件和 74 个已登记产物；本轮没有修改这些源码或产物、五项受保护基线，也没有放宽网络或保存/退出阈值。

## 实现和审查结论

| 实现 | 具体行为 | 当前验证与限制 |
| --- | --- | --- |
| 异步连接与重试 | 原 IntegratedFrameSyncClient 使用解析、连接和重试定时器；每条物理连接有独立 generation，旧回调失效。断线重试间隔从 100ms 递增到 1s，保留原始 30s 总期限。 | 两个真实客户端交替断开、丢失恢复确认后的再次重试均通过；完整负面协议矩阵仍待执行。 |
| 会话与快照 | 校验比赛、槽位、协议契约和凭证代次；I/O 线程有界组装快照，游戏线程恢复状态并核对哈希，随后才发送 Ready；Accepted 后恢复输入发布。 | 两种构建的实际快照、连续权威后缀及 AI 接管/交还通过；没有降低状态验证条件。 |
| 输入与操作 | 同步重置输入历史与发布时钟；丢弃断线期间尚未发送的动作短按，保留仍按住的方向和窗口命令；窗口持续处理保存、退出及重连标题。 | 真实 XTEST 方向/冲刺、短按射门、保存和退出通过 Release 窗口检查；完整 ASan 图形恢复仍未通过。 |
| 心跳与 RTT | 真实客户端每 500ms 发送心跳，匹配服务端回显后计算 RTT；不使用测试器制造的心跳维持连接。 | 无头和弱网两种构建通过；固定 1000 帧捕获边界后仍转发真实心跳，等待实际客户端追平。 |
| 回放 | 保留正常连续回放 V1；有恢复快照时保存 V2 分段回放，支持断线期间保存已确认前缀，并逐段独立复演。 | 旧格式、原子存储、容量约束已有前轮组件证明；本轮实际客户端保存文件继续进行交叉引擎校验。 |
| 首次表现层初始化 | 从 connect_recovery 的窗口主线程移到现有 tick_buffered 游戏/GL 工作线程；后续恢复使用同一线程。 | 实际窗口复现旧候选首帧前线程归属异常，修正后通过；原线程所有权断言保留。 |
| 草皮视觉随机 | GeneratePitch 的草纹选择改用现有视觉随机源 random_non_determ，避免消耗比赛 RNG。 | 实际图形与无头初始哈希重新一致；原无头初始哈希和首个物理帧哈希在 Release/ASan 均保持不变。 |
| SDL 线程资源 | 外部游戏/GL 工作线程退出时通过 RAII 调用 SDL_TLSCleanup；正常退出和异常展开均覆盖。 | 104 字节 SDL 泄漏有旧失败/新通过对照；最新真实 ASan 图形客户端退出无泄漏，但仍触发初始化超时。 |

SDL 官方说明外部创建且调用 SDL 的线程应在退出前清理线程局部资源；工程使用本机已提供的 SDL2 清理入口。[SDL3 生命周期说明](https://wiki.libsdl.org/SDL3/SDL_CleanupTLS)、[SDL2 API](https://wiki.libsdl.org/SDL2/SDL_TLSCleanup)。

## 实际证据

- 客户端 E 的双客户端 Release/ASan 共 104884 条断言通过；四组独立保存回放复演及输入重置检查共 49072 条断言通过。它们是历史候选证据，不能替代后续图形修正的验证。
- 客户端 F 的两种构建实际双客户端恢复回归通过。弱网矩阵追加每个接收批次 20/25/30/35ms 延迟和抖动、保持字节和记录顺序的 TCP 分片写入；两种构建共 104976 条断言、6362 个延迟批次、36996 次分片写入通过。每客户端确认 1000 帧，包含三次断线和一次恢复确认丢失。此结果不覆盖 UDP 丢包、乱序或所有弱网组合。
- 草皮 P：图形、无头、表现层初始化后的状态哈希均为 1086847095508428874；首个中立输入物理帧均为 12693704928474537033，两种构建一致。此前图形初始哈希为 12960387446322928366，逐字段证据显示比赛 RNG 多消耗一次；首帧后才重新一致，旧回放检查因此没有揭示启动握手问题。
- 最新客户端 G + P 的真实 Release 窗口：恢复 Accepted 边界 399；检查区间的 22 帧全部收到真实方向/冲刺，短按射门未在恢复后泄漏，松键后权威输入清零。断线期间保存 0.076360s，再次断线期间退出 0.139573s；91 次渲染、105 次引擎步进，窗口确认 441 帧、10 个权威哈希、1 个恢复检查点，第二客户端确认 1000 帧；两个客户端和服务端均正常退出。
- 最新真实 ASan 图形退出检查：游戏初始化完成后触发原有连接期限，客户端退出码 1、服务端退出码 0，未再出现 ASan/UBSan/LSan 报告。这只证明失败路径的资源清理；约 100.4s 的初始化运行仍不满足完整图形启动和恢复要求。
- 最新交叉回放已全部完成：修正后的 P 引擎分别以 Release/ASan 重放两组弱网实际保存文件、U-D 窗口以及最新 G 的 U-F 窗口，共 8 次独立复验、84768 条断言通过。每次都核对完整 1000 帧权威轨迹，并重新加载实际恢复快照、实际保存的输入片段和断线期间的 V1 前缀；最新 G 窗口每种构建重放 1142 个实际保存记录。见[六组复验](../optimization/benchmarks/native-recovery-client-verified-journals-20260914-a/report.json)、[最新 G 窗口两组复验](../optimization/benchmarks/native-recovery-client-final-window-replay-20260914-a/report.json)。证据正在封存，整体质量状态仍不提升。

## 保留的失败和验证边界

所有候选版本、失败日志与编译产物保留。A 编译重复声明和定时器 API 问题、B/C 测试捕获边界不足、C 缺少心跳、D 恢复元数据前的合法心跳被拒绝，均有后续修正，历史失败不改写为通过。E 首次回放 oracle 的结果字段沿用旧值造成驱动失败，实际引擎断言已通过；V 纠正字段后重新完成全部交叉验证。

窗口 U-A 暴露表现层线程错误，U-B 暴露图形初始 RNG 差异。U-C 的方向计数曾将位掩码 512 当作帧数；独立原始权威记录审计确认真实 22 帧，U-D 及之后的完整测试使用布尔计数。U-C 的 ASan 版本记录了初始化超时和 104 字节 SDL 泄漏。

U-E 的保存超过 3s，随后测试清理中的一次等待异常跳过了服务端清理。已核对精确 PID、启动标识、目录和参数后终止该测试残留服务端，确认消失。U-F 保持产品阈值，增加即时进程身份记录，并保证逐个清理。同期另一个私有显示测试的命名空间退出曾等待文件系统写回；它与 U-E 保存迟滞的因果关系尚未确认。后续私有临时 overlay 使用 volatile，父环境挂载与系统配置不变。

SDL 小型测试的早期版本另有 GL 上下文重复移交和未释放测试上下文的问题；完整原始日志保留。最终 T-D 在实际工作线程释放测试 GL 上下文后，对正常退出和异常退出分别验证 TLS 清理，没有泄漏屏蔽项。
