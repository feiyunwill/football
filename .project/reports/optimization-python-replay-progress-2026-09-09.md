## 实现与修正

新增 `gfootball/replay_io.py`，读取端只依赖标准库与 NumPy，不需要导入 Gym、原生引擎或 OpenCV。每次解码一条记录，检查输入文件与序列化记录容量，再使用现有 `ObservationState` 验证和持有数据。通过文件身份、长度和修改时间检测读入过程中及 reset 时的变化。只有精确到达文件尾才视为正常结束；截断 pickle 或非法尾部明确报错并关闭文件。

旧 `load_dump()` 保留列表及可写数组的兼容行为，同时限制记录数与实际保留字节。新 `iter_dump()` 提供逐条读取。共享动作读取器只持有第一条记录中的配置与当前动作行，释放完整观察；同环境、同解析路径的 22 个消费者可以共用一次逐帧解码，独立环境保持独立进度。消费者不能越过尚未读取本帧的其他球员，reset 也按组完成。耗尽抛出库异常 `ReplayExhausted`，不再结束宿主进程。

文本导出不再提前截断已有目标。`AtomicReplayFile` 使用实际目录预算和临时文件，写完、flush/fsync/关闭后再替换明确指定的目标；解码、序列化、容量或写入失败保留旧目标。文本按记录流式输出，数组使用显式、有界的显示设置，避免构造整场回放的字符串或修改全局 NumPy 设置。这是单文件替换，不代表目录或 dump/video 组合的事务持久性。

播放转换使用物理频率计算观察频率。100 Hz 物理、每观察 20 步对应 5 FPS，转换到 10 FPS 插入一个空动作；60 FPS 无法表示为整数物理步，明确拒绝。转换要求原记录从零开始连续，保留全部原动作边界，不接受静默降采样、重复帧或缺帧。私有转换文件只保存动作与首条配置，不复制观察数组。

`ScriptHelpers.replay()` 不再修改传入的配置更新，不再全量展开回放。它使用自有临时目录，环境成功、异常和中断路径都先关闭环境/球员/文件再清理目录。清理失败不替换原始错误；提前 EOF 也不会伪装成成功播放。播放步数有转换后记录数的上界，零外部控制球员或显式玩家覆盖也能停止。

真实 `FootballEnv` 接入每环境一个 `ReplaySourcePool`，构造失败会关闭已创建的玩家，close 会关闭玩家、共享源和核心环境。只有 replay 玩家收到内部池引用，其他玩家配置不会混入不可复制的锁对象。左右队伍分别计算动作偏移，修正右队定义排在左队之前和单个玩家控制多个球员时的取值顺序。球员数量在构造及重复列表分配前验证。

审查还发现 `_get_new_env()` 只在新建引擎时设置物理步长，复用引擎可能继续使用旧播放频率。核心 reset 现在也应用当前配置的物理步长。这一接入修正尚需实际 GameEnv 验证，不能由纯 Python 时序计算测试替代。

## 默认边界

| 对象 | 默认限制与超限行为 |
| --- | --- |
| 输入 | 文件 128 MiB、序列化记录 32 MiB、10,000 条；拒绝并关闭 |
| 兼容列表 | 保留数据与列表容量 256 MiB；拒绝，建议逐条迭代 |
| 私有转换 | 文件 128 MiB、100,000 条，含插入及末尾 10 条空动作 |
| 文本 | 128 MiB，失败保留原目标 |
| 动作缓存 | 合计 8 MiB，最多 22 源、22 消费者；不保留观察 |
| 观察结构 | 继承 `RecordingLimits` 的单步、debug、节点、深度及数组边界 |

缓存统计计入配置、动作名称/字段、索引与预留的 reset 集合容量。每源 64 KiB 文件缓冲和固定控制对象由源/消费者数量另行限制。返回给调用方的记录、临时解码/复制空间、任意 pickle reducer 分配、原生与 GPU 内存不属于这些保留字节统计。回放文件仍必须来自可信来源；对象跨 fork 共享不受支持。
