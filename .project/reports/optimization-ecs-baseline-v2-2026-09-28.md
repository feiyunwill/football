# ECS 比较基线迁移与正式复测

归属 ms-21.1 → plan-21.1.1 → task-21.1.1.2。历史 `baseline.json` 指向已丢失的 `/tmp` 引擎二进制，旧基线的正式比较无法重跑。保留它及既有失败日志，不把缺失归档重建成未经证明的原版。[第二版基线清单](../optimization/baselines/ecs_v2.json)明确采用提交 `739d767d84c788b93481522e7106298b6d818efd` 的正式比赛原始记录与变更前二进制；两份压缩二进制存放在同目录，压缩和原始 SHA-256 均在清单中。验收脚本先验证源码身份、资源与输入，再解压到独立临时目录，检查动态链接和两种子轨迹。

旧门禁针对当时的 `full_cache` 优化，要求旧版各 40,000 次分配、新版 0 次；第二版参考代码已达到 0 次，因此新比较要求双方继续为 0，同时要求候选版整场稳态帧的分配次数和字节数均下降。两种子各 15 对未插桩独立进程、CPU bootstrap 95% 区间上界小于 1、墙钟几何均值小于 1、配对 p99 中位比不高于 1.05、输入与全部状态检查点一致的条件保持不变。测试另验证清单不能把 CPU 上界放宽到 1.01。这是从已完成优化之后建立的新起点，不改写旧基线的历史结论。

独立预检通过：仓库二进制在新目录加载，固定种子 42/43 的轨迹与归档一致，共 122 项断言。见[预检摘要](../optimization/evidence/ecs_v2_preflight_20260928.json)与[原始数据](../optimization/evidence/ecs_v2_preflight_20260928.json.gz)。正式重验的框架、架构和当前 11v11 比赛基准均为 `verified`。新版 ECS 门禁完整执行 60 个进程、两个独立分配采样和 1,590,027 项断言，无跳过；比较结果只有两项失败：种子 42/43 的 CPU 改善均未确立。当前/基线 CPU 几何比为 0.9981/0.9576，95% 区间分别为 0.9620–1.0359、0.9067–1.0028。墙钟比为 0.9982/0.9574，配对 p99 中位比为 0.9917/0.9893。两种子的整场分配次数与字节数都下降，`full_cache` 双方保持零分配；每对输入、预热、状态检查点、最终哈希及活跃标志均一致。
