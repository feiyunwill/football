# 长局逻辑性能与 RSS 验收契约

对应 ms-21.1 → plan-21.1.2 → task-21.1.2.2。实现与状态由 quality.py 按当前输入验证，产品阶段仍未完成。

入口 `engine_soak_benchmark SEED CPU` 固定 1000 个预热逻辑帧、36000 个测量帧，种子 42／43 各一个独立进程。沿用默认 11v11、四外部控制槽位、十个物理 tick／逻辑帧的真实引擎。每帧推进 100 ms 模拟时间，测量区间是 3600 秒模拟时间；实际循环墙钟、CPU 时间与进程总时长分别保留。此入口不进行一小时墙钟配速，不能作为渲染、网络或物理输入设备延迟证明。

采样数组在引擎启动前构造并逐项写入，随后恢复空数组追加方式，保留经过对照验证的采样器修正。不从 RSS 减去估算值、不修剪分配器、不在测量中重建或重置引擎。输入及采样规则与已保留的长局轨迹一致，原短局基准源码继续按不可变基线指纹验证。

每个种子必须同时满足原五项要求：

- 全部稳态逻辑帧的 p99 严格小于 50 ms。
- 六个连续 6000 帧窗口的 p99 均严格小于 50 ms。
- 全部稳态 RSS 检查点的最大值不超过预热 RSS 加 4 MiB。
- 后四分之一 RSS 中位数不超过前四分之一中位数加 256 KiB。
- 最后三个窗口的 RSS 中位数极差不超过 256 KiB。

分布及窗口均从完整原始样本重算；保留每 100 帧的 RSS 和状态检查点、活动标记及输入哈希。快照恢复后重演全部输入。两个种子与仓库内版本化的 v8 长局参考逐一比较输入、预热、终态、状态检查点及活动帧标记。v8 使用传球缓冲反向取消语义对应的 ECS v10 参考引擎、原长局入口二进制和同一性能回滚补丁；清单位于 `.project/optimization/baselines/soak_v8.json`，原始双种子报告及基线／候选验证日志均保留 SHA-256。生成工具为 `.project/optimization/diagnostics/soak_reference_refresh_v8.py`。v2–v7 参考及 `native-soak-20260910-a` 历史报告保持原样，不把旧玩法轨迹或历史 RSS 失败改写成当前通过结果。

前置条件是当前源码对应的完整检测、容量及固定 15 对／种子的短局 CPU／p99 对照均已 verified。长局新增入口不替代这些前置条件。执行器核对 Release、C++23、无 sanitizer／fast-math、原基线编译器版本、实际加载核心、全部测量前后源码与二进制指纹。全部日志、参考指纹、构建参数、机器信息、失败和超时均保留；失败不自动重跑，不筛除长尾样本。

执行 `python3 .project/quality.py run task-21.1.2.2`。20 项校验器与真实进程清理测试纳入质量自检；构建、两种子完整长局及依赖检查均需以当前版本实际执行，局部预检不替代正式状态。

2026-10-04 的 v7 正式长赛记录位于 `benchmarks/performance-regression-1791069068310361979/report.json`，两种子合计 212 项断言、零跳过。种子 42／43 的稳态 p99 分别为 8.193431／6.947654 ms，五项长赛预算与轨迹对照均通过。该记录只覆盖无渲染长赛；当前输入和手感任务仍需各自的正式门禁。
