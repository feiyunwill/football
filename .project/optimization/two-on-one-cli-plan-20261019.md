# O21：正式 CLI 的 balanced 推理与恢复

目标：将 O20 已冻结的 balanced 动作选择纳入 native_ppo_train，保留训练、argmax 和采样行为。
新推理入口只支持固定 simple115 的有界 2v1；不新增学习效果结论。

实现与验证：

1. FPPO 原有源码/构建/ABI/资源检查不变。用原兼容引擎先校验五个 O20 模型完整字节，显式导出仅策略 FPOL1；禁止用改写身份的方式迁移训练快照。
2. 新 CLI 提供明确推理模式、场景文件和 FIFS1 会话状态；保存原生状态、DIC1 额度、RNG、配合历史与累计指标。错误模式/版本/输入/校验和必须拒绝。
3. 当前源码重新执行完整质量门槛。正式 CLI 五个模型各200回合，所有主要回合 JSONL 与 O20 逐字节一致；原 argmax 和采样对照也核对。
4. 跨进程拆分运行与完整运行回合行完全一致；校验当前构建会话能恢复且不同构建的原生快照被拒绝。
5. 用同一批短场景测量两种策略的进程墙钟、CPU、最大 RSS 和决策吞吐；说明场景轨迹不同造成的测量范围，不将吞吐差异当作纯控制器加速比。单独测量 policy.forward+动作选择与控制器状态大小。
6. 当前正式 CLI 与当前核心库打包，在独立目录运行1000主要回合。归档解压后实际执行复现脚本并比对SHA256，保留安装测试与完整收据。

历史 O20 新确认起点本轮仅用于一致性回归；不再次宣称独立学习确认。生产变更后不能复用旧源码质量收据作为当前验收。构建与运行串行，不改动历史接受的构建、模型和归档。
