# 查询与分配优化契约

对应 task-21.1.1.2。以已完成任务 21.1.1.1 的不可变二进制、输入和实际轨迹为对照。

## 保留的行为

QueryResult 在每次 Execute 中重新发现组件池，选择最小池的有序实体视图构造结果；结果只保存实体 ID。清空世界并重新建立组件池后，可以再次 Execute。缺少组件类型时返回空结果，不分配空组件池。

QueryBuilder::ForEach 先固定匹配集合，再逐实体读取组件。前一个回调删除后续实体或组件时跳过失效匹配；回调新建的匹配不进入本轮。组件池地址只在当前调用期间缓存。

World::ForEach 的单组件与双组件重载保留第一个池的候选 ID 快照。双组件回调可以向尚未访问的原候选添加第二组件，此行为不因选择更小候选池而丢失。三组件重载按最小池固定候选 ID，修复了不同 ComponentPool 类型不能相互赋值的编译错误。所有候选保持实体 ID 升序；删除及添加造成底层组件向量扩容时，下一次访问重新按实体获取组件。

与其他 C++ 容器视图一致，Clear/移动世界会使活动遍历及组件引用失效；不要在遍历回调中清空或移动整个世界。对池的结构修改也会使先前取得的组件引用失效，不应在修改后继续使用该引用。

## 正式比赛路径

RunPlayerSystems、SyncPlayerPhysicsSystem、PopulateCollisionResults 和 SyncEcsFromOop 在每次调用入口取得本次需要的组件池。缓存不跨比赛、重置、快照恢复或线程共享。球员实体顺序和 OOP 权威数据流保持不变。

TeamStateFillSystemDirect 搜索球队实体时使用只读有序视图；搜索期间没有回调或池结构修改。新球队实体的创建发生在视图遍历结束之后，因此无需复制实体列表。

## 证据要求

- engine_hotspot_profile 是 Linux/glibc 的独立诊断库，生产目标不链接它。它通过动态符号包装记录指定函数的包含子调用耗时，以及基准线程上的 malloc/calloc/realloc 次数与请求字节数；不是实际在用堆大小或所有线程的内存统计。
- 区间与真实比赛基准一致：前 200 个 StepWithInput 预热，之后 2000 个逻辑帧计数，随后的 2000 帧重演不计数。无渲染固定单实例，每种种子均检查 21 个状态检查点和全部 2000 个比赛进行标志；缺少包装符号或区间不符必须失败。
- 初始诊断：种子 42/43 的完整帧分配次数分别为 1432072/1776524，full_cache 均为 40000 次、640000 字节。需要复测证明该同步阶段的稳态分配归零，且真实比赛总分配下降。
- 运行时间比较使用无诊断库的独立进程，每种种子十五组相邻基线/候选，交替谁先运行；两种种子也交替执行。保留逐帧原始数据与每一组结果，不能挑选最快批次。
- 要求每种种子的配对 CPU 均值比例，经 10000 次固定种子 bootstrap 得到的 95% 区间上界小于 1；wall time 几何均值比例小于 1；配对 p99 比例中位数不得退化超过 5%。这些短时统计不替代后续总体性能预算。
- 每个过程都进行快照重演，基线与候选的输入、预热、途中、最终状态及比赛进行标志完全一致。源码、编译器、资源、基准输入与两套二进制均核对身份。

执行 python3 .project/checks/ecs_performance.py。失败也保留原始比较文件，继续修正，不以修改阈值、删去慢样本或跳过失败获得通过。边界回归及前置完整框架/架构门禁属于正式任务验收的一部分。

## 动画查询分配（正式失败后的继续优化）

首次正式比较保留在 ecs-comparison-1788938218118548256.json：种子 43 的 CPU 比例区间上界为 1.0009686958335076，未证明提升；不改变阈值、不删除该次样本。

独立 operator new 调用点采样（allocation-callers-before-43.json）显示，2000 个稳定帧中 tokenize 产生 314280 次分配，Animation::GetVariable 两处产生 212082 次分配。调用点表固定 4096 项，记录溢出数量；采样时间不混入无插桩性能统计。

新增 GetVariableRef/get_ref 保留原有按值 API，以透明比较器查询字符串键并返回属性引用。引用只在当前读取期间使用；同键更新和缓存生命周期结束后不能继续使用。动画选择、人体运动和触球路径使用该只读 API，保持筛选顺序和数值公式。

GetVectorFromString 保留原来的逗号分隔、忽略空段及 atof 转换。最多三个坐标使用字符串视图，短 token 复制至 128 字节栈缓冲区并显式终止；长 token 使用原有字符串路径。没有直接把原始字符串后缀传给 atof，因此逗号小数点区域设置不会改变 token 边界。没有引入浮点转换替换或全局可变缓存。

engine_animation_query_contract 将新结果与旧解析路径逐位比较，覆盖缺失坐标、重复分隔符、带后缀文本、嵌入空字符、负零、科学计数法、溢出/下溢及栈缓冲边界；另有 10000 组固定生成输入和属性引用生命周期检查。Release 门禁执行该契约，完整架构门禁另用全核心 ASan/UBSan 构建执行。

正式动画优化验收前，已完成五对进程的预检 ecs-comparison-1788939575403759109.json。它通过原门禁，但种子 43 的 CPU 95% 区间上界 0.9997946353627828 仍很接近无提升。考虑本机频率未锁定且观测效应约 1%–3%，在正式运行前将样本量预先固定为每种种子 15 对进程；完整保留这 60 个进程的 120000 个稳定帧样本，不做提前停止或可选样本剔除。原五对预检、先前正式失败的证据继续保留，不合并成可选择的正式样本。CPU 区间、wall 均值和 p99 阈值均不改变。

## 2026-09-28：可持久复现的第二版比较基线

原 `baseline.json` 保留为历史证据；它指向的 `/tmp` 引擎二进制已丢失，不能据该指针重新宣称通过。第二版基线明确选用提交 `739d767d84c788b93481522e7106298b6d818efd` 的正式 11v11 原始记录与变更前引擎二进制，二者的源码身份、二进制哈希及每种子轨迹相互匹配。压缩二进制及清单存放在 `.project/optimization/baselines/ecs_v2*`，原始比赛记录另有受哈希保护的仓库归档。验收器在独立临时目录解压，检查压缩与原始哈希、资源和测试输入、编译器及动态链接，再按固定两种子重新运行；`--baseline-preflight` 只校验基线与轨迹，不代替正式性能验收。

原门禁要求旧版 `full_cache` 每种子 40,000 次分配、候选版 0 次。第二版参考代码已经完成该优化，故要求参考版和候选版都保持 0 次，避免既有收益回退；同时仍要求候选版真实比赛稳态帧分配次数与字节数都低于第二版参考。每种子 15 对未插桩进程、CPU bootstrap 95% 区间上界小于 1、墙钟几何均值小于 1、配对 p99 中位比不超过 1.05、轨迹逐项一致等条件不变。第二版是新的比较起点，不补写或覆盖旧版未能重跑的验收结果。

## 2026-10-01：手动反向规则后的第三版比较基线

手感优化在 `PlayerController::_MovementCommand` 加入严格反向规则后，原 v2 与当前候选的固定比赛轨迹不同。为避免用不同游戏语义比较 ECS 性能，第三版参考在 v2 源提交上仅应用归档的 `ecs_v3_manual_turn.patch`，从隔离构建生成新引擎、基准程序与十次比赛原始记录。清单 `ecs_v3.json` 记录父版清单、补丁、源码身份、记录和二进制的 SHA-256；原 v2 文件原样保留。

使用同一规则的旧 ECS 与当前 ECS，在种子 42/43 的输入、预热、最终哈希、状态检查点和比赛进行标志逐项相同。正式验收仍执行每种子 15 对独立进程、原 CPU bootstrap、墙钟、p99、完整轨迹和分配断言；`--baseline-preflight` 只验证归档可重跑。第三版更新是比较语义的同步，不改变任何性能阈值，也不把手感任务视为已完成。

第三版正式比较记录在 `benchmarks/ecs-comparison-1790798488052128372.json`，两种子各 15 对进程、1,590,027 项断言全部通过。种子 42/43 的 CPU 几何比为 0.827843/0.819105，bootstrap 95% 上界为 0.883789/0.906167；墙钟几何比为 0.827823/0.819062，配对 p99 中位比为 0.855714/0.826330。原始记录包含第 7 轮明显慢于基准的样本，未剔除。该结果只证明当前 ECS 实现相对同语义参考版通过既定性能门槛，不证明手感任务已经达标。
