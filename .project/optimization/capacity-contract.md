# 网络与回滚容量验收

2026-09-13。归属 ms-21.1 → plan-21.1.2 → task-21.1.2.1。

验收对象是输入、历史、日志、连接收发及录制的明确容量边界，以及填满、拒绝、释放、再次使用的真实行为。正式结果由 `quality.py` 根据源码、依赖和执行证据计算；创建检查脚本或收集报告不代表通过。

| 对象 | 当前默认边界 | 过载与恢复证据 |
| --- | --- | --- |
| C++ 权威输入 | 最多 22 槽位、1024 帧、512 KiB 保留输入容量 | 拒绝非法长度/NaN/超限，消费和终止回收，真实 TCP/UDP 收发 |
| C++ 快照 | 单快照 1 MiB、历史 8 MiB，历史帧数另有限制 | 超限前拒绝推进、回滚增长、失败后的再次确认，实际 GameEnv 快照 |
| C++ 待确认 UDP | 256 包、256 KiB | 数量/字节分别填满，ACK 释放、重传耗尽、并发发送、真实无 ACK 退出 |
| C++ TCP 发送 | 每连接默认 256 项、2 MiB，包含待派发及发送中的数据 | 排队前预留，慢端超时，健康连接继续，关闭和取消回调回收 |
| C++ 内存回放 | 100000 帧、32 MiB 保留容量 | 到达上限保留已确认前缀，最大长度流式输出、独立解码 |
| C++ 回放目录 | 64 个文件、256 MiB 逻辑文件数据；替换峰值计入旧文件和新临时文件 | 同一目录跨进程锁；满额拒绝、不删除已发布文件；释放容量后可重试 |
| C++ 日志与渲染队列 | 日志每条最多 4096 字节；渲染队列按类型固定对象容量 | 并发日志与截断，实际纹理引用、溢出和异常后恢复 |
| Python 网络、回放及资源所有权 | 每个所有者分别限制输入、帧/哈希历史、发送队列、重试和录制目录 | 全部 frame_sync 当前回归；实际文件/编解码/跨进程目录；真实 Core/GameEnv 创建、渲染和销毁 |

原生目录预算针对使用同一策略的协作写入者和 Linux 本地文件系统。默认最多扫描每个目录 4096 项；扫描限制必须容纳文件和专属临时目录。`.football-replay-tmp-v1` 是应用保留的 0700 临时目录，只回收其中严格匹配原生临时文件名、当前用户所有、无其他硬链接的常规文件。未知条目和父目录的旧临时文件保留且计入预算；不扫描子树，不清理历史质量报告或用户目录。最多一个新临时文件持有写入锁；文件数量限制针对保留文件，字节限制同时覆盖该临时文件。超时或容量拒绝不发布新文件，发布后的同步错误明确报告 `committed=true`。

原生持久化先同步文件，再原子重命名，最后同步临时和目标目录。锁采用目录文件描述符，持锁进程异常退出后由内核释放。边界依据 Linux [`flock`](https://man7.org/linux/man-pages/man2/flock.2.html)、[`rename`](https://man7.org/linux/man-pages/man2/rename.2.html) 与 [`fsync`](https://man7.org/linux/man-pages/man2/fsync.2.html) 的语义；不推广为任意 NFS/SMB 或非协作写入者的保证。

执行入口：`python3 .project/checks/memory_budget.py --output <不存在的新目录>`。普通与完整 ASan/UBSan 构建顺序执行，编译使用 `-j 1`；检测器泄漏检查开启，无抑制。对故意 `SIGABRT` 的日志场景，仅验收退出原因，不宣称其正常析构或泄漏检查通过。UDP 故障代理最后终止其自建服务端，也不将该服务端退出计入正常析构验收。协议探针、真实 GameEnv 和纯容器用例分别保留报告。
