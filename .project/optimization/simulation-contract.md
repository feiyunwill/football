# 逻辑、表现与快照契约

2026-09-09，`task-20.1.2.1`。是否完成以 `quality.py` 当前证据为准。

`step()` 和 `StepWithInput()` 推进固定数量的物理 tick。`render()` 只准备并提交表现数据，不能增加逻辑帧或改变 canonical 状态摘要。验收在真实 EGL 渲染器上把同种子、同输入的有图形/无头环境逐帧比较，并在两个 step 之间重复调用 render。

`GameEnv::get_state()` 返回 v2 快照。16 字节外层头包含 `FSTA`、版本、载荷长度和 CRC32。完整性和长度在修改比赛状态之前验证；载荷上限为 10,000,000 字节。CRC32 检测损坏，不承担身份认证。载荷针对本阶段支持的 Linux little-endian ABI；不承诺任意平台二进制兼容。旧的无版本快照被明确拒绝，不能继续作为当前 `set_state()` 的输入。

随机数状态通过 MT19937 的状态读写接口规范化为 624 个 32 位字，不再恢复随机数对象的内部数组游标或分布对象内存。逻辑摘要也使用该表示，因此摘要字节和 hash 会随格式变化；跨进程一致性与恢复后的未来轨迹仍需实际验证。

反序列化约束：

- 标量和诊断 reference 先检查剩余长度；浮点必须有限，布尔必须是 0/1，枚举在转换前验证所属类型的合法值。
- 向量和四元数按浮点成员处理，禁止把未知对象作为原始内存复制。引用表保持具体指针类型，检查负数和上界；必需对象引用不能为 null。
- 通用容器及每个手动变长容器均有数量和剩余字节限制。球队、控制器和静态动画对象数量必须与当前场景相符，不能 resize 出空指针再解引用。
- 动画游标、预测缓存游标、控制器镜像和球队索引在被后续逻辑使用前校验。

`set_state()` 保留完整备份，在当前环境的实例锁内恢复。校验和解析错误发生时，先退出临时镜像状态，再恢复场景及完整比赛备份，最后重抛原始异常。不会用重启比赛替代恢复原帧。若备份恢复本身失败，则关闭环境并报告恢复失败，避免暴露半恢复对象。

镜像转换中的球队索引、触球归属、犯规位置、重启位置与控球统计通过局部值处理；历史感知树先在临时副本解码，避免清理过程中解引用半填充的历史球员指针。成功恢复后统一刷新 ECS 查询数据。

验收入口为 `.project/checks/simulation_contract.py`。其原生测试会重新封装损坏载荷并计算正确校验和，让故障到达真实解析路径，包括多处截断、接近末尾的截断、无效球队和历史球员引用、非法布尔/枚举/浮点、空输入、错误版本和多余尾部。每次失败都检查当前逻辑摘要和 TLS，再验证继续比赛及恢复重演。两个种子分别覆盖正向和反向球队处理，图形对照使用真实 320×180 EGL 帧。

本任务不替代 `task-20.1.2.2` 的完整 ASan/UBSan、长流程状态转换和桌面 SDL 集成检查，也不替代后续网络与性能里程碑对格式协商、快照成本和故障条件的验收。
