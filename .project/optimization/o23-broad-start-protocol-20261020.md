# O23：broad80 与原训练分布的预登记实验

本协议承接O22草案与试运行。候选设计和资源上限已登记；执行器在当前源码质量通过后，写入不可变的source/tool/binary/protocol哈希，再开始训练。当前源码候选实现为独立 `2v1_broad`、任务标识4及FPPO内层schema4，原2v1仍为标识3/schema3。

## 唯一候选与固定对照

baseline为原12点2v1训练分布；broad80为20%原分布、80%五类连续几何分布，各类等概率。奖励、配合历史与sticky观测、固定AI队友、19动作、PPO参数保持一致。五种子42、123、2026、31415、271828；hidden64、epochs4、minibatch64、rollout256、2048更新、cadence10、episode_limit256。

每个训练运行分为8段，每段256次更新，段间使用完整FPPO跨进程恢复，以留下真实更新进度。最终2048次更新是唯一候选检查点，禁止按中间验证成绩选模型。全部10次训练结束后才评估验证集。两配置按种子交错顺序执行，奇数序号种子先candidate，其他先baseline；不调换失败种子。

几何由每回合引擎种子和版本化C++采样器确定。独立工具按episode RNG重建 `completed_episodes+1` 个起点，保守地可能多排除一个未使用的末尾起点，后续新确认须排除这些引擎种子和几何。

重建日志的geometry记录引擎FormationEntry实际存储坐标，并同时记录formation_y_scale与球位置。该类型会将构造参数y乘以负的缩放常数；后续确认去重必须换算到相同引擎坐标空间，不能将原始y直接与存储y比较。

## 运行预算

O22实测64更新16,384转移约18.17秒，完整/分段模型一致。每个完整训练运行墙钟上限1283秒，10次训练总上限12830秒；子进程观测RSS上限512 MiB，研究输出上限2 GiB。训练、编译和评估串行；超限保留失败记录并停止，不追加种子或降低门槛。

每次最终模型验证最多300秒，10次验证合计最多3000秒；辅助几何重建每个模型最多120秒。资源采样、逐段模型和命令退出码全部保存。上述是预算，不是预期耗时或性能达标结论。

## 验证门槛

仅使用旧200个broad验证场景。broad80需均值至少92%、每种子至少83%、每种几何类别跨模型均值至少82%；每模型完成传球与配合进球回合率至少20%；均值比匹配的新训练baseline至少高2个百分点。候选仅一个，不作超参数搜索。

全部验证门槛通过后，才冻结唯一候选并登记新的200场景确认集。确认继续使用八周路线的均值93%、每种子85%、每类85%、配合指标及相对O20冻结模型的配对区间门槛。旧确认结果不能作为本轮新的独立证据。

## 验收边界

当前源码质量必须先通过。FPPO的source/build/ABI/resource校验及跨任务拒绝保持严格，FPOL1只用于推理。完整学习或长期目标失败时如实记录，不把短试运行的可恢复性或高配合率当作93%目标通过。
