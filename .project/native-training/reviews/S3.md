## 边界与状态

1. Profiling 只属于 NativeTrainingEnv diagnostics。默认关闭时 timer 不调用
   时钟，仍有 flag/branch 成本；启用后 advance 的 action/engine/info/
   transition/encoding/reward 分段保持原执行顺序。step/step_many 持有既有
   mutex；profile enable/reset/query/record 用 mutex，enabled 为 atomic。
   binding 在 GIL release 内推进，GIL 恢复后复制 NumPy/tuple，output 计时
   只覆盖这部分。NumPy 不引用临时 C++ buffers。诊断计数不是并发 epoch
   事务，正常 Python owned 环境要求创建线程使用。
2. 精确 get_state/set_state 源码确认 profile/clock/counters 不参与 snapshot，
   kernel digest 仍来自 GameEnv；格式未扩展。C++ 类布局/源码身份增加，
   依照已有同 build/ABI 约束要求重编译，不承诺旧二进制 ABI 或跨 build restore。
3. NT-3.2 容器候选已撤回，最终 Ball/BallComponent 无阶段 diff；没有跳过
   物理、Mirror 或 spatial updates。采样不足/WSL波动明确披露，收益表不是
   通用性能保证；不把 residual 全部归为 binding。
4. worker 固定 spawn，每个进程主线程创建自己的 native env。没有把 parent
   engine、Gym RNG 或资源 lease 传给 child。1..4为 per-pool 上限；独立worker
   各一引擎，host RSS不是硬配额，multiprocessing内部resource tracker是
   预热后保留的运行时进程。父进程有一个同步请求/worker，帧最多32KiB，
   metadata/config最多8KiB；selector 写读共享 deadline。半帧、超大header、
   请求身份/shape/finite值、远端异常、退出均 fail whole pool。
5. 整轮动作/episode预验证先于发送；无自动retry/reset。错误轮其他worker的
   已完成动作无法回滚，因此关闭整组，调用者显式决定重放。正常close先请求
   native cleanup，再join；错误terminate/kill/join，释放Process handles。
   同process/thread ownership在公开操作前校验。停止进程的kill升级另行实测。
6. episode seed v1 与 worker数量/分配无关。collector策略读取reset/上一转移
   观测，PolicyContext只含episode/seed/step；复用action buffer先验证并脱离，
   pre/post回调数组隔离。summary 有界，stream保留的数据和callback时间由
   调用者拥有；不把IPC deadline冒称为Python callback deadline。
7. horizon仅标truncated，真实match终态terminated优先；stream带最终观测，
   供后续算法正确bootstrap。没有PPO、learner checkpoint或策略RNG恢复承诺。
   逐步trajectory与final kernel hashes用途区分，不能替代完整training state。
