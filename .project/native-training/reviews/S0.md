## 全局影响复核

- **仿真与确定性**：GameEnv 动作/物理实现未改写。默认/v2 action IDs、右队
  旋转、球队填充、active one-hot、奖励符号和结束条件对照现有实现。1/2/11
  agent、稀疏阵容、真实进球、恢复同 seed 及批量前缀均有实际状态哈希对照。
- **生命周期与并发**：批量 admission 先检查完整输入；共享 advance 统一单步
  和批量语义。C++ mutex 串行化本对象，Python owner 在调用前检查 thread/PID。
  mutation/output failure 关闭并返还资源，非法 batch 保持状态。未由此宣称
  GameEnv 可在同进程多线程并行采样；S3 先采用进程隔离。
- **GIL/内存**：整数输入复制至 C++ 所有的 vector 后释放 GIL。释放期间不
  创建 Python 返回对象或读取原始 NumPy 参数。返回数组在重获 GIL 后分配，
  其数据不被下一次 step 覆盖。容量最多 256×11 个 transition rows。
- **原有 Python/Gym**：默认 backend 路径保留，增加的 owner 检查仅对 native
  生效。全部 9 项原有真实引擎测试通过，包含 RGB/终态、legacy 四返回值和
  wrapper 快照、构造/输出错误释放、向量环境与 RNG。
- **渲染/网络/录制**：未更改这些组件的实现或协议。原有 Gym 渲染有运行回归；
  没有重新运行全产品网络/soak/渲染预算门禁，因此其原有未完成状态不提升。
- **构建/打包**：新 core/binding/test 源文件均登记；bindings OFF 不查找 Python
  绑定。core 被现有 setuptools CMake 目标使用；wheel 安装及多平台仍由 S5
  实际验证，不能把 staging 当已安装包。
- **验收工具**：输出目录必须新建；raw logs 保留原始字节并记录哈希，日志末尾
  工具产生的空行用仅作用于 evidence logs 的 Git attribute 豁免。构建串行、
  输出位于隔离目录；没有修改既有 `.project/quality.py` 或里程碑状态。
