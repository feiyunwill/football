# C++ 训练链路长期计划

制定日期：2026-10-14。执行入口：[任务状态](state.json)。

## 长期目标与完成条件

建立共享 C++ 训练环境内核，供 Gymnasium 和原生训练程序使用。Python 承担
训练生态接入、场景编排和分析；动作、观测、奖励、终止、快照及采样核心逐步
统一到 C++。最终提供可复现的策略训练、评估、恢复和发布流程。

完成条件：

1. 支持范围内的 Python/C++ 观测、奖励、终止和状态哈希有固定种子对照证据。
2. 训练环境及策略检查点恢复可重复，格式和兼容性版本明确。
3. 单步、预设动作批量和按观测决策的闭环采样均有独立测试及测量。
4. 多进程采样有资源上限、异常退出处理和可复现种子分配。
5. 一个原生离散策略训练入口完成真实训练更新、评估和恢复；算法语义明确。
6. Linux Python 包与纯 C++ 产物可从干净环境构建、测试和使用。
7. 每阶段通过全局 review，未解决的阻断项为零；平台限制明确记录。

原生训练路线与现有 `.project/quality.py` 的产品验收并行记录。这里的阶段通过
不自动提升 `ms-25.1` 或其他既有里程碑，也不替代其依赖和验收检查。

## 固定执行流程

每次只推进一个子任务：读取状态和依赖 → 图索引/源码核对 → 实现 → 针对性
测试 → 检查 diff → 独立 Git commit → 登记 commit 和证据 → 下一个任务。

- 每个任务一个逻辑提交；修复可有后续独立提交。提交消息带任务 ID。
- 验收失败时保持任务进行中；修复并重验，不能为了形成提交而宣称完成。
- 仅暂存本任务文件。其他已有修改保持其原有归属。禁止全目录 `git add .`。
- 已授权任务提交；普通提交无需重复询问。push、合并或发布另按明确授权执行。
- 构建使用隔离目录和 `--parallel 1`。记录源码指纹、命令、返回码和环境版本。
- 状态修改与证据随下一次任务/review 提交保存；commit ID 由提交后的 Git 输出登记。
- 不因测试数量或单次加速结果判断阶段完成。性能比较固定场景、动作、种子，
  交错执行并报告波动，同时验证最终哈希。

每阶段全部任务提交后，执行一次整体 review：

1. 复核整个阶段 diff、调用边界、共享状态、生命周期、异常处理和接口兼容性。
2. 检查对训练、原有 Gym、引擎、网络、渲染、录制和构建/包装的影响。
3. 执行阶段集成检查，确认测试覆盖了真实路径，证据对应当前源码。
4. 将问题分为阻断、一般改进和后续阶段事项，保存 `reviews/Sx.md`。
5. 阻断项必须修复、测试并独立提交，然后复核。通过后提交 review 和状态。
6. 只有 review 通过，下一阶段才能进入进行中；不要求用户重复回复“继续”。

review 由当前执行者以单独审查轮次完成，明确证据范围；不将自审称为独立审查。
