## 命令行和菜单

在具备原生运行环境的项目目录中执行：

```text
python -m gfootball.frame_sync.local_play --frames 300 --record recordings/match.jsonl --save recordings/local.save
python -m gfootball.frame_sync.local_play --resume recordings/local.save --frames 100 --record recordings/continued.jsonl
python -m gfootball.frame_sync.local_play --replay recordings/match.jsonl
```

输出目录由现有持久化层管理，完整文件采用临时文件、同步和原子替换。`--save` 在 P 键或正常达到帧数/按 Q 结束时保存；`--resume` 使用存档里的场景、控制槽位数与种子。`--record` 在正常结束时发布完整回放。中断、输入回调、引擎、容量或写入故障不会把部分录制作为成功文件替换已有回放。Ctrl+C 会结束并封存已有录制，不自动覆盖比赛存档。

`--fast` 关闭真实时间节拍，适用于有帧数上限的自动运行。非交互运行必须指定 `--frames`，允许 1–1000000 帧；场景名称可由 `--scenario` 指定。`--left` / `--right` 是两队的受控槽位数，其他球员使用引擎 AI。当前本地键盘只占用槽位 0，不再接受无效的多槽位控制声明。

## 运行与资源所有权

本地服务直接绑定端口 0 后读取实际端口，消除了“先找空闲端口再绑定”的竞态，也不再用固定 sleep 猜测启动完成。一个服务端线程拥有权威引擎，创建 `LocalPlayer` 的线程拥有客户端副本、输入和文件操作。所有 API 使用同一个本地比赛所有者，重入 step 和跨线程推进/保存/关闭会被拒绝。

## 文件内容与限额

比赛存档是一份专用单槽位集合，沿用 SaveManager/SaveStore 的版本、SHA256、全量原子写和跨进程冲突控制。首次创建也一次发布完整槽位，不先写空存档。引擎状态最多 1 MiB，每 24576 原始字节编码为一个 Base64 块，最多 43 块。载荷与图结构使用已有上界，比赛存档单槽位/总载荷预算均为 2 MiB。解码先检查全部尺寸、块数和编码长度，再分配最多 1 MiB 的原始结果，校验规范 Base64 与 SHA256。

比赛录制继续使用 ReplayManager 的帧、事件、集合和文件预算。含原生初始状态的文件显式使用 `football.frame_replay` v2：MATCH_START 保存场景、种子和初始状态元数据，STATE_SNAPSHOT 事件保存各个有界块，MATCH_END 保存最终规范状态摘要和下一帧号。每个快照事件最多 8 个 4096 字符串，满足单记录 64 KiB 上界。普通历史回放仍写 v1，v1 不接受原生快照事件。

每一帧保存真实球和球员位置以及完整权威输入。回放先完整验证文件校验和与初始快照，再创建引擎、恢复原点、逐帧执行输入，对比每帧位置及最终状态摘要和比分。续玩是新的本地网络时间线，帧号从 0 开始；原生比赛状态继续，续玩录制携带独立完整原点，可以单独重放。

默认原生适配器要求 Linux、64 位、小端与约定物理节拍。权威/逻辑实例无窗口，显示工厂使用固定渲染角色；两者具有相同的物理身份。它从 `/proc/self/maps` 识别实际 Python 扩展和引擎库，检查设备/inode并哈希库、策略源码及数据/字体。身份在构造、保存与恢复边界验证，逐帧不重新读取资源；详细限制见[图形所有权](graphical_match.md)。

指纹读取每次最多 64 KiB，单文件最多 256 MiB、单次文件集合最多 512 MiB、最多 8192 个遍历条目和 512 个目录、深度最多 16。路径和描述符分别检查读取前后的元数据；Windows 不把两类 API 的不同 ctime 直接当作文件变化。指纹不在逐帧路径执行，也未启用仅凭文件时间戳信任内容的缓存。文件边界检查不能替代操作系统或存储系统的延迟保证。

旧 `match_checkpoint` v1 没有身份信息，恢复和覆盖写入会明确拒绝并保留原文件；旧的原生回放若携带 v1 原点，也在构造引擎前被拒绝。没有猜测版本或尝试原生反序列化来迁移旧数据。自定义 `engine_factory` 必须显式提供 `get_snapshot_identity()`，返回上述四个有界字段；没有未知后端的自动兼容回退。

快照仍是不透明原生数据，身份字段不构成签名或来源认证。这一实现不代表跨版本迁移、任意来源原生快照的安全反序列化、云同步、整个进程的 RSS 或产品性能验收。Linux 库识别与真实 GameEnv 执行仍待验证。
