# 展示姿态插值与回滚过渡

2026-09-10。图形比赛已接通 Python 展示时序与 C++ 球、骨骼、相机插值入口。当前数值、时序、实际 socket/文件与所有者回归通过；C++ 尚未编译，真实原生中间图像检查尚未执行，不能据此认定实际画面达到产品质量。

## 时序

`LogicStateHolder.read_pair()` 在一次锁保护下读取最后两个不可变快照，最多返回两个借用引用，不复制载荷。历史仍按原来的条目数和字节数限制。显示较慢时选取最近的相邻逻辑端点，不补绘全部过期状态。

`PresentationLoop(..., interpolate=True, logic_hz=10)` 要求显示引擎提供 `save_render_state(from_display=False)` 和 `render_interpolated(alpha)`。图形入口强制使用这些方法；缺少新绑定时明确失败。通用 PresentationLoop 默认仍使用普通 render，原有使用方式不变。

正常相邻逻辑帧的插值比例为 `clamp((显示时刻 - 最新逻辑发布时间) × logic_hz, 0, 1)`，从前一帧显示姿态过渡到最新帧。因此正常展示带有约一个逻辑间隔的缓冲延迟，不是额外推进物理。只改变确认号或等待标志不会重置状态发布时间。停止收到状态后最多到达已知端点，不外推运动。

初始状态直接展示。回滚、同帧纠正、历史中断使用最近实际绘制的姿态作为过渡起点；该纠正过渡从本次显示时刻开始，用一个逻辑间隔趋近已纠正物理状态。纠正尚未结束又有新目标时继续从已显示姿态衔接，避免强行跳到尚未显示的逻辑端点。该过渡只作用于显示副本。

`run_one_frame(settle=True)` 显示精确的最后端点，后续同状态绘制不会倒退。图形比赛退出前使用它处理终局与最终权威校正；正常退出、错误清理、录制和回放验证仍由原有所有者完成。

## 原生路径

新绑定 `GameEnv.save_render_state()` 在恢复下一个快照之前捕获显示端点。`from_display=True` 选择已绘制姿态，用于纠正过渡；它要求本显示环境已经完成绘制。新 `render_interpolated(alpha, swap_buffer=True)` 接受有限的 0–1 比例，要求已保存渲染姿态，并通过现有上下文锁和 tracker 守卫调用 `GameTask::PrepareRender(alpha)`。

普通 PrepareRender 仍调用 Match::Put；插值分支调用 Match::PutInterpolated，随后执行原有蒙皮更新及几何上传。球插值位置和旋转；相机插值位置、旋转、视场角及裁剪距离。alpha=0 保留起点旋转，alpha=1 使用普通 Put 的精确终点。

人物原有插值只临时修改 spatialState，而实际 Put 从骨骼节点读取姿态，因此未能改变用于绘制的骨骼。本次改为插值 fullbody 位移和蒙皮实际使用的各骨骼显示位置/旋转，同时更新头发。每个人物最多保存 64 个显示关节姿态，超过容量明确失败；不保存额外完整游戏快照。队伍及裁判传递相同的镜像坐标选择，未激活球员的历史失效，避免重新出现时使用过期姿态。

这些缓存不进入 ProcessState，也不修改 logical spatialState 或动画节点。重新 reset 会清除环境的渲染历史标志。所有原生语义仍须实际引擎确认，尤其是规范摘要、蒙皮形状、裁判持牌等附属物、摄像机运动和多场景切换。

## 裁判持牌

2026-09-10 后续修复：普通与插值绘制共用持牌处理。附件位置从蒙皮显示关节、fullbody 位移和人物缩放计算，不再直接读取当前逻辑动画节点；左右手均使用同一个局部偏移，红牌与黄牌分别选择正确物体。缺失关节、不再持牌或恢复到普通动画时隐藏旧牌。

牌色、持牌手和可见性是离散状态。插值期间保留捕获端点的离散状态，alpha=1 才切换到目标状态；从实际显示姿态开始纠正时，也捕获当前画面中的牌色和持牌手。字段不进入物理快照。隐藏和未变化的物体不会重复调用场景变换更新。
